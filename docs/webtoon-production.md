# 縦読み制作で採用した知見

第1〜10話までの実例は[武侠転生譚の連載原稿](../examples/swordsaint-enemy-disciple/README.md)に保存した。第2〜10話では、食事・呼吸・階段・稽古・手当てを小さな動作に分け、仇への疑いを残したまま進める。63場面の原画から各話26〜28の非重複表示窓を組み、石段や回廊は連続絵として読む。

生成された分割位置は均等ではない。画像ごとに目視して境界を決め、木剣が金属化した場面と、師匠が誤って現れた器の大ゴマは修正生成した。紋章の形が異なる再登場部分は採用窓から外した。新作9話は390px幅で約29〜30画面、360px幅でも文字19px以上で横はみ出し0を確認した。4〜6分は制作目標であり、読了時間の実測値ではない。

更新日: 2026-10-05。実際の試作とスマートフォン幅での検証から、採用した判断をまとめる。

『天魔、二周目。』第1話では、最強の身体と本人の理解・感情を分けて改稿した。縄の痛み、失った日常、力を試す行動、成功への驚き、防御の理由、生還後の震えと安堵をつなぐ。山場を長老との一戦へ絞り、次の剣の謎は音だけに留めた。[感情と行動の因果](../skills/webtoon/references/emotion-and-causality.md)に絵コンテと修正前後の実例を同梱する。

称号・効果音・武技名は文字を含む生成画像へ変更し、システム表示は金装飾から整列した窓、さらに文字と枠がにじむ半透明の投影へ調整した。読めることと、作中の視界として自然かを別々に確かめる。[生成文字とシステム表示](../skills/webtoon/references/system-and-lettering.md)に比較画面と生成指示を保存した。

## スクロールを物語の時間にする

横長の漫画を縦に並べるだけでは、次の絵が先に見えてしまい、読者がスクロールする意味が弱い。幅を狭めるだけでも解決しなかった。

最初に「いま何を見せ、何をまだ見せないか」を決める。短い動作や応答は密に置く。正体が現れる前、聞き耳を立てる場面、衝撃のあとには、文字のない余白を広く取る。読者自身のスクロールが、待つ・たどる・近づく動きになる。

余白をすべて同じ長さにしない。「手掛かり → 無言の距離 → 正体」のまとまりを作る。1コマを必ず1画面に合わせる必要もない。雨だれ、足跡、石段、巨大な生物の輪郭などは、連続した縦構図の途中を画面が通過するように描く。

## 作画と文字の方式を選ぶ

現在の新作の既定は、日本語の会話を縦書きの吹き出しとして絵に含めて生成する方式。[縦書きの採用実例](../skills/webtoon/references/vertical-lettering.md)を参照し、全文、列順、話者、尾、顔や手を隠さない位置を指示する。画像内の文字は画像生成で編集し、HTMLで個別編集できるとは説明しない。

個別に文字を編集する指定がある場合や、既存のHTML会話を部分改稿する場合は、HTMLまたは構造化データから重ねる方式を使う。『天魔、二周目。』の会話はこの既存方式を保ち、表情と演出を直した。人物・小道具・負傷・持ち手の状態を絵コンテに残し、画像にある文字をHTMLで二重に置かない。

余白だけを直す場合は、採用済みの作画を再利用する。再生成は人物や演技、構図そのものの修正が必要な場面に限定する。武侠版では、庇う左腕・一本の暗器・破れた袖が救出後もつながることを確認する。

## スマートフォンで検証する

基本の確認幅は390×844と360×800。横方向にはみ出さないこと、セリフが縮小されず読めること、吹き出しが顔や重要な動作を隠さないことを確認する。19px前後を起点に、文字量と実画面を見て調整する。

正体を隠したい場面は、手掛かりの終わりから「正体を識別できる最初の画素」までを測る。画像の上端にはまだ顔がないことがあるので、画像要素の位置だけを測って済ませない。全長スクリーンショットで流れを確認し、さらに画面単位でスクロールして登場順と間を確認する。

配信サービスの画像寸法・分割・容量規定はサービスごとに異なる。調査時の数値を一律のWebtoon仕様として扱わず、投稿前に対象サービスの最新要件を確認する。

## アプリに収録する

作品の正本は各例の`index.html`と参照画像。iOSアプリはこれらをバイト変更せず同梱し、WKWebViewで読む。セリフ、縦構図、余白、背景色、登場順を保持し、通信なしで読める。

作品メタデータの正本は[content/catalog.json](../content/catalog.json)。[同期スクリプト](../scripts/sync_ios_webtoons.py)が参照画像とHTMLを`ios/Manga/Webtoons`へコピーする。ポチのようなJSONから作るコマも拾う。欠落画像・外部依存・作品外参照は同期時に失敗させ、`--check`で収録物と正本の差を検出する。

白背景版と初稿は同じ第1話の別版。制作バージョンを第2話と誤表示しない。カタログに載せない過去版も、比較できるよう`examples`へ残す。

## 再利用するスキル

[skills/webtoon/SKILL.md](../skills/webtoon/SKILL.md)に、制作手順・成功例・広い余白の比較・プロンプト・HTML補助ファイルを一式で収録した。インストール後は`$webtoon`で呼び出せる。更新する場合はrepo側とインストール側の差を確認する。

2026-10-06にシリーズ設計を追加した。新規シリーズの全体話数が未指定なら最初に一度だけ50話・100話・200話以上の3つから規模を選んでもらう。指定済みなら聞き直さず、未回答を200話以上の選択として扱わない。世界観・人物・物語を往復して設計し、選んだ規模のロードマップと直近10話の詳細を分ける。制作依頼の初回範囲は第1〜10話の読める完成原稿。短編・設計のみ・指定話数・既存作品の依頼はその範囲を優先する。

設計手順は[全体と長期構成](../skills/webtoon/references/series-planning.md)、[世界観](../skills/webtoon/references/worldbuilding.md)、[キャラクター](../skills/webtoon/references/character-design.md)、[導入10話](../skills/webtoon/references/opening-arc.md)、[複数話の制作と再開](../skills/webtoon/references/batch-production.md)に分けた。将来の計画、脚本、作画、表示確認の完成を別々に管理し、制作済みの設定と各話の状態を次の制作へ引き継ぐ。
