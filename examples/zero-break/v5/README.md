# 第1話 v5 — 接近と測定の流れ

**[縦書き完成版を読む](index.html) / [全体画像・390px幅](complete-390.png)**

前版の2枚に集中していた騎士の説明と魔力判定を16場面へ分け、全30場面に拡張した。騎士は足音、離れた姿、声かけの順に近づく。レンは立ち上がり、案内に従って装置まで歩く。測定は方法の説明、ためらい、接触、待機、ゼロ表示、驚き、意味の説明、落胆を順に描く。

16枚を組み込みimage_genで新規作画し、救出以降を含む14枚の採用原画は前版から保持した。絵・吹き出し・縦書きセリフを一緒に生成している。文字を変更する場合は対象の画像を再編集し、余白と配置はHTMLで調整する。

## 制作ファイル

- [絵コンテ](storyboard.md)：距離、歩行、手の位置、本人の理解と感情、各場面の間。
- [場面データ](manifest.json)：セリフ全文、列順、読み順と原画の出所。
- [生成指示・測定器の修正指示](PROMPTS.md)：新規16枚の指示。保持14枚の指示は[前版](../v4/PROMPTS.md)。
- [編集用HTML](index.html) / [組版生成スクリプト](build_reader.py)：画像内のセリフをHTMLで重ねない。
- [表示と目視確認の記録](validation.json) / [360px幅の全体画像](complete-360.png)。

`art/` は完成原画30枚。`source/` は測定器や立ち姿を直す前の原画。[実行記録](generation-log.json)から編集元と採用ファイルを追える。`review/scene-360-*.png` に全30場面のスマホ表示を保存し、390px幅の代表的な連続画面5枚も収録する。検査の実行時は両幅の全場面と全スクロール画面を再生成する。

390×844と360×800で全30枚の読み込み、横あふれ、二重表示を検査した。360px幅で全場面のセリフ、話者、衣服、手と装置の状態を目視し、390px幅の連続画面で接近、歩行、測定待ち、結果と次の事件を確認した。待つセリフの下端から０の見え始めまでは、画像内の位置を保守的に選んで896.5px／827.6px。完成画像は390×19737px、360×18246px。

## 再構築

このディレクトリで実行する。

```sh
python3 build_reader.py
python3 package_delivery.py
npm install --no-save --package-lock=false playwright pngjs
node check.cjs
```

検査スクリプトを実行すると目視確認の状態がpendingへ戻る。セリフと作画をスマホ表示で読み直して検証記録を更新する。画像内の文字の読みやすさはDOMのフォント値では測れない。

全体画像はブラウザの通常のスクロール画面を順に繋いで書き出す。長い一括キャプチャで起きた16384px地点の冒頭重複を避け、原画の画素を加工しない。[書き出し検証](raster-export-validation.json)では全区間がスクロール画面と一致し、冒頭の重複がないことを確認した。

前版の[生成指示](../v4/PROMPTS.md)と人物参照の原画2枚を収録している。全50話の場面脚本は[脚本目次](../series/README.md)。2〜50話の作画は未制作。

単独HTMLは[reader.zip](reader.zip)を展開して開く。原画を変更せずHTMLをZIPに格納し、展開後のバイト一致は[配布検証](delivery-validation.json)に記録する。`reader.html` 本体は再生成するためGitの対象から除外する。
