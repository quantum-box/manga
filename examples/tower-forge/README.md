# 塔を灯す剣

[第1話から読む](episode-01/index.html) · [第1〜10話の一覧](chapters.html)

VRMMORPG《星環の塔 ONLINE》を舞台に、自分の作った剣で塔の頂上を目指すカイと、盾役のセナ、魔法使いのイリスを描く初稿。剣と魔法の王道の冒険に、有限の部品で作る装備、試験、連携、共同工房を組み込む。

## 制作範囲

2026-10-07、読者から初稿の密度、1話の短さ、展開の速さ、状況と共感の不足を指摘された。第1話を描き直し、登りたい動機、セナとの関係、試作品の不具合、確認、試験、勧誘の意味を順に見せる。追加指摘を受け、現在は78の物語上の瞬間・22枚の原画。ステータス、装備詳細、試験ログ、パーティ参加を実際の操作として追加し、《灯刃・試作》の効果とカイの得意分野を見せる。約束の余韻の後に、塔の巨大な光環、東門封鎖、工房街の停電を追加。通知を読んだカイが工房へ戻る選択で終わる。第2話は同じ夜に続き、原因と復旧条件を知る。第2話は20枚・60の物語上の瞬間へ改稿。停電の続きから、イリスとの出会い、遠征の約束、通常のログアウトと翌日のログイン、水路の保守入口までを順に描く。第3〜10話は改稿・公開待ち。各話を PR、マージ、サーバー公開、公開確認の順で一話ずつ届ける。

台詞と縦書きの吹き出し、横書きのHUDは原画に一体生成。各話の `index.html` は画像参照式。第2話以降の改稿は `reader.html` も同じ参照式とし、原画を二重に内包する巨大なHTMLをGitに保存しない。単一HTMLが必要な場合は `python3 skills/webtoon/scripts/package_reader.py examples/tower-forge/episode-02/index.html --output /tmp/tower-forge-episode-02-reader.html --force` で同じ原画から作る。既存の第1話は内包リーダーを維持する。第1話の全長記録はブラウザーから3分割で保存した `webtoon-390-part-01.jpg` など6枚。順序と範囲は `validation.json` に記録。第2話は改稿全編の実際のブラウザー撮影を両幅で4分割ずつ保存。記録は `validation/browser-390.json` と `validation/browser-360.json`。第3〜10話の `webtoon-390.jpg` と `webtoon-360.jpg` は初稿の全長画像。原画と台詞の増加だけで、読者が理解できると確定しない。

第1話は発話と効果音を別に設計し、7枚の部分編集で13箇所の動作音を整えた。無言の動作にも音を入れ、聞く表情や安堵には無音を残す。効果音は吹き出しへ入れず、音源の近くに描き込む。実行済み指示は [PROMPTS-USED.md](episode-01/PROMPTS-USED.md)、修正済みで未実行の次回生成指示は [PROMPTS-NEXT.md](episode-01/PROMPTS-NEXT.md) に分けて記録。

HUDも発話・効果音と独立させた。灯刃は斬撃を30％強化する魔導剣。カイは市販型と同じ効果を半分のMPで出す回路を設計する。熱は強化の際に回路へ残る損失で、溜まると安全装置が強化だけを止める。回路設計68・剣術12という現在の技能を、成果と試験を伴って描く。新しい窓の入力には5箇所の短い電子音を加え、塔の前兆・轟音・封鎖・消灯・通知・一歩に7音を加え、現在の効果音指定は計25箇所。

縦積みの密度への追加指摘を受け、8枚の構図を描き直した。塔・街の経路・最後の夕景を枠なしの縦の背景へ、短い二打と問い・返答を同じ段の右→左へ、三打目と成功後の安堵を待つ間へ分ける。装備の画面と再試験は別の縦横比を使い、当時の18枚を同じ1:3の縦横比と構成へ固定しない。既存68の瞬間、全文の台詞、HUDの内容、18音は維持。今回の4枚では前兆を小さな接写、大きな異変を一つの長い枠なし風景、街への影響を短い動作、決断を無音の間と一歩に分けた。キャプチャと読順の確認は `validation.json` の `scroll_review` に記録する。

200話以上の指定に対し、[240話の全体構成](series/roadmap.md)を12アークで仮設計。第11〜240話は長期構想であり、完成作画や各話の詳細脚本ではない。改稿後の読み心地へのユーザー評価は未確認。

## 確認と再構築

390×844・360×800 CSS pxで画像読み込み、横はみ出し、画像内の縦書き、話者、所持品、場面の順を確認する。最新の実施状態は [制作状態](production/status.md) と各話の `validation.json` に記録。技術的な表示確認と、読者が流れを理解できるかは別の判断。物理スマートフォンやiOS実機の確認ではない。

```sh
python3 examples/tower-forge/production/build.py
python3 examples/tower-forge/production/verify.py
python3 scripts/sync_ios_webtoons.py
python3 scripts/sync_ios_webtoons.py --check
```

組み込み image_gen の原本を保存し、必要な修正だけ編集機能で作った。現行画像は `production/adopted-assets.json`、初稿の原本は `production/asset-provenance.json`、第1話改稿の原本と正確な実使用指示は `production/revision-provenance.json`。再構築は各話の採用済み `episode.json` から行い、画像生成を再実行しない。旧稿の本文・絵コンテと採用済み改稿の専用スクリプトは削除し、過去の内容はGit履歴から復元する。現行版が編集に参照した原画・実行指示・検証資料は残す。

ローカルのカタログとiOS同梱データへ収録。ユーザーの指示を受け、制作物とスキル更新をGitHubのPRへ提出する。第2話のサーバー公開は PR・main への取り込み後に行う。公開確認の証拠は話別の記録へ保存する。TestFlight配布はこの作業の対象外。

19枚目の低い振動音は複数コマから大きな白い余白へ続き、21枚目の門の衝撃音は枠と斜めの間を越えて消灯コマまで響く。継続する一つの音として記録し、会話・顔・手・通知を避ける。[実行した編集指示](production/sound-bridge/manifest.json)。
