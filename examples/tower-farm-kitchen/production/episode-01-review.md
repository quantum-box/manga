転移直後に帰還門を尋ね、初対面の店で飯代を働くと言い出す前稿を改稿。説明する側だけが知る情報と、主人公が聞いてから選ぶ行動を分けた。第1話40場面のうち13枚を新しい原画へ差し替え・追加し、18回の生成を使った。第2〜10話は今回の導入改稿の対象外。11〜240話はロードマップで、完成作画ではない。前稿はGitコミット`0bdf643122d94500790d6f5e8c14c783db981f70`。旧リーダーの別版やZIPは残さない。

## 知る順序

剣を見て戸惑う → 石壁と自分の手を確かめる → 「ここはどこですか」 → 係員がけがを確認 → 塔の三階だと聞いて見上げる → 畑から突然来たと伝える → 他にも来訪者がいると知る → 元の場所へ帰りたいと伝える → 係員が初めて帰還門を教える → 再開時期は分からない → 今夜の休憩室を案内され、礼を言う → 閉じた門を実際に見て受け止める。

係員の顔、灰髪と短いひげ、濃紺の飾り布を初対面の原画へ揃えた。帰還の成功や日付は保証しない。

## 依頼を受ける順序

持ち物は作業道具だけ → 湯気と包丁の音を追って店へ着く → 水だけを頼む → 店主に勧められて座る → 水を飲んで礼を言う → 食事を勧められる → 金がないと断ろうとする → 店主が農家か尋ねる → 七年の経験を伝える → 店主が畑の点検に一食を提示する → コウが了承 → 店主について畑へ移動する。

水を頼む場面から仕事の了承まで、同じ窓口でコウは外側の右に座り、エルナは内側の左に立つ。道具を食事台へ載せない。点検への対価なので、作物を即時に治す約束もない。

## 料理の質感

続く読者フィードバック「食べ物は美味しそうに、つぶつぶを強調しすぎない」に合わせ、調理・配膳・ひと口の3原画を4回の組み込み生成で改稿。初回は粒の密集が残ったため採用せず、それを入力にして煮汁をなめらかにした。肉・人参・葉の大きな形、穏やかな艶と湯気を見せ、柔らかく煮た麦は煮汁の下に置く。同じ器と料理、仕入れた食材、台詞・効果音・表情・手・萎れた畑を保った。第2〜10話は今回の食品改稿の対象外。

全長を増やしたことを理解の改善の証拠にせず、問い・説明・聞いた反応・次の選択を順に読む。湯気、畑への道、水路の連続原画と、土・鎧・歩み・木蓋・泥・水・厨房の効果音24箇所は原画へ統合。予兆の下端から水が出る次の原画までは390px幅で936.59px、360px幅で864.55px。一画面を超え、結果の先出しはない。

13枚の修正箇所を両幅の確認シートと実際の画面高の画像で目視。全文、縦列、話者、係員の外見、同じ席とコップ、手・工具を確認。全長スクロール、40枚の読み込み、横あふれ、通常版と同梱版の全長一致を再確認。同梱版で復元した40枚のPNGは原画のSHA-256と一致する。

料理改稿の確認で、Chromeの一括全長キャプチャが32,768px以降を冒頭の画素で繰り返す不具合を発見。旧PNGの当該区間と冒頭1,000行が両幅で完全一致することを確認した。現在は390pxの48画面、360pxの47画面を実際に撮影し、表示画素を連結して全長PNGへ出力する。全95画面の画素一致、冒頭の繰り返し解消、390px全長画像の最後に新しい食事と明日の会話があることを確認。原画のバイトは変更していない。

同梱リーダーは`reader.html`と同じフォルダーの`reader-art-01.js`〜`03.js`を一緒に使う。原画のバイトを変更せず、GitHubの一ファイル100MiB制限に合わせて格納ファイルだけを分けた。通常版とiOS版は原画PNGを直接読む。配布物Pythonテスト11件、格納方式の往復と分割テスト4件、iOS同期チェックとSwiftの読書コンテンツ確認を実行。
