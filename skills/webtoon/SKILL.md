# Webtoon 制作

スマホでスクロールして読むシリーズや短編を、物語・世界観・人物の設計から作画・文字組み・表示確認まで仕上げる。**余白とスクロールで時間・感情・情報の出現順を演出することを制作と完成判定の中心に置く。** 縦長の画像、等間隔のコマ列、横並びや斜め枠の追加だけでは完成としない。

## 本作画の前にネームで構成を見せる

新しい話の本作画や、構成を組み直す大きな改稿へ進む前に、[構成ネームのプレビュー](references/name-preview.md)を使う。「ネームを見せて」「構成を先に確認したい」「ラフで一度見せて」という依頼もここへ進む。対象の一話について、白黒の粗い絵、読めるセリフ、効果音、反応、コマの大小と余白を縦に読める形で先に提示する。完成作画の前に構成を直せることが目的で、文字だけの絵コンテや枠の一覧をネームの代わりにしない。完成作画を保つ軽微な文字・余白・表示の補修には、新しいネームを必須にしない。

この制作環境では、ネームを開いて画像も会話へ表示し、ユーザーの返答を待ってから本作画へ進む。「見せてそのまま進めて」と明示された場合は、提示後も内部確認して続ける。ネーム先行モードは提示までを成果物とし、ユーザーが構成を採用する前に完成作画を始めない。各コマの承認待ちを一律に追加しない。

ネームで使った構成と文字を `storyboard.md` へ反映してから、本作画の指示を作る。ネームの確認を完成原画・完成リーダー・公開確認の合格へ広げない。

## 一話を十分な長さにする

通常話は**幅390 CSS pxで本編高34,000〜60,000 CSS px・内容区間高24,000 CSS px以上・有効80〜120コマ**を基準とし、[一話の長さと読み応え](references/episode-length.md)に従う。内容区間高は本編高から純余白を除いた値。本編高34,000px未満、内容区間高24,000px未満、有効コマ80未満のいずれかなら分量を見直し、理解・応酬・反応・山場・結果の不足を補う。数字の達成だけで合格にせず、余白・再分割・説明の言い直しによる水増しも確認する。

390px幅での実際の表示寸法を使い、原画像の解像度やファイルの分割枚数を分量にしない。読了時間は任意の補助情報とし、合否条件にしない。ネーム提示時に本編高・純余白・内容区間高・有効コマ数の目標と実量、物語のまとまりを伝え、ユーザーの返答を待つ。短編・特別回・部分試作・別の長さの指定は対象範囲と理由を明記し、通常話を制作都合で短くしない。

## 一話ごとの抜けを防ぐ

作画・縦ラフ・表示を制作または改稿する話では、発見、大きな動作、重要な会話、場面の切り替わりの該当箇所について、次の4点を絵コンテへ記録し、作画指示と完成した表示へ引き継ぐ。短い連続動作はまとまりで扱ってよい。未記入を「演出不要」と解釈せず、必要な判断を済ませてから作画する。脚本・設定だけの依頼では、該当する設計項目までを扱い、作画や完成表示の照合を追加で要求しない。

| 項目 | 作画前に決めること | 完成した表示で照合すること |
| --- | --- | --- |
| 余白 | 待つ位置と理由、直前の手掛かり、次に初めて出す情報、置く要素。密に読む区間は詰める理由 | 実際のスクロールで待ちや余韻が続き、答えが先に漏れていないか |
| 音 | 動作の発生音、前からの継続音、意図した無音を区別。必要な音の語句・発生源・開始と終わり | 指定した音が実物にあり、音源とつながるか。共通の文字禁止や表示窓で消えていないか |
| 接続 | 場所・時間・人物・目的の変化、直前の結果、次の行動のきっかけを伝える絵や言葉 | 読者がここまで見た情報から、今どこで誰がなぜ動くかを辿れるか |
| セリフ | 会話では相手へ求めること、関係と口調、言葉にする感情と隠す本音、聞いた後の反応。心の声では本人の疑い・願い・決意などの目的 | セリフ・表情・手・呼吸・間が同じ場面の感情を伝え、相手の反応や本人の理解・選択へつながるか |

音の欄は各まとまりで「新しく鳴る／前の音が続く／効果音を描かない（理由）」のいずれかを明記し、発話がなくても省略しない。歩く・触れる・受け渡すなどの動作がある箇所は、その動作音を描くかも判断する。
発生源や素材が未定で音を決められない箇所は確認待ちとして残し、意図した静けさと分ける。

意図した静けさ、短い応酬、急な場面切り替えも選べる。その狙いを残し、全コマへの大余白・効果音・感情説明を合格条件にしない。セリフの書き方は[感情と行動の因果](references/emotion-and-causality.md)を使う。

作画後はこの4点を該当するスマホ幅の連続画面と通読で照合し、`validation.json` または制作資料へ箇所・確認結果・残課題を記録する。指示に書いたこと、画像の読み込み、文字の正確さだけで演出を確認済みにしない。抜けや不一致があれば、その箇所を補修して読み直す。実物を確認できない項目は未確認として残す。

## 読者向けのタイトルと紹介

作品名、各話タイトル、話一覧、紹介文には物語と読者に必要な情報だけを載せる。「日本語縦書き」「原画統合版」「改稿版」「初稿」「vN」などの制作版ラベル、作画方式、コマ数、制作工程を付けない。制作方法・改稿履歴・検証結果は制作資料へ記録し、読者向けカタログの `edition` は空にする。今後の新作・改稿・公開にも適用する。

## 最初に制作規模を合わせる

新規シリーズの全体話数が未指定なら、最初に一度だけ **「全体で何話くらいの規模を目指す？」** と聞き、**「50話」「100話」「200話以上」** の3つを標準選択肢として提示する。自由回答で別の話数・シーズン数・短編が指定された場合も尊重する。これは作品規模の質問であり、制作許可や各話の承認を求める質問ではない。

ユーザーが「少なくとも200話」などと既に指定していれば聞き直さない。非同期の質問ツールが使えれば一度だけ出し、回答に依存しない既存資料の確認を続ける。規模に依存するロードマップと脚本は回答を得てから作り、未回答を200話以上の選択として扱わない。「おまかせ」と明示された場合は200話以上を目標とする。長さが指定された短編・読み切りや既存作品の部分修正ではこの質問を挟まない。

## 依頼の範囲と初回の制作単位

新規シリーズの制作では **選んだ規模の物語全体を設計し、初回は第1〜10話を読める完成原稿まで制作する**。全体話数はユーザーの選択に従い、10話を初回の制作単位にする。世界観・人物・物語を往復して設計し、長期ロードマップと直近10話の詳細を分ける。全話の詳細脚本や作画を初回の要件にしない。

| 依頼 | 設計・制作する範囲 |
| --- | --- |
| 新規シリーズを作る | 選んだ規模の全体設計、主要人物と世界観、第1〜10話の完成原稿 |
| 企画・世界観・人物・脚本だけを設計する | 指定された設計成果物。作画は依頼された場合に進める |
| 既存シリーズを続ける・修正する | 既存の設定・話数・採用版を読み、依頼範囲を制作。既存作品を自動で200話へ延長しない |
| 短編・読み切り・指定話数を作る | ユーザーが指定した長さと成果物を優先する |

シリーズ企画では[全体と長期構成](references/series-planning.md)、世界観を設計するときは[世界観](references/worldbuilding.md)、人物を設計するときは[キャラクター](references/character-design.md)を読む。新規シリーズではこの3つを使い、設定同士の矛盾と物語を継続できる根拠を確かめる。成果物の `series/bible.md` を入口に、世界観・人物・ロードマップ・連続性の台帳を保存する。

初回の制作前に[第1〜10話の導入アーク](references/opening-arc.md)、複数話を仕上げるときに[まとめて制作・再開する手順](references/batch-production.md)を読む。本作画前のネームは提示して返答を待つ。採用後の作画・表示確認は内部で品質を確認しながら進め、各コマの確認待ちは追加しない。実際の制限で途中になった場合は、完成範囲と残作業、再開位置を記録する。計画・脚本・ネーム提示と採用・作画・表示確認の完了を区別する。

## 最初に読む実例

作画・縦の絵コンテへ進むときは[承認された実例](references/approved-example.md)を読み、同梱の完成画像を画像表示ツールで見る。特にコマの密度差、雨だれと足跡の縦の動線、音や問いから答えまでの距離を見る。これは構成の判断材料であり、物語・6場面・猫・夜色・特定の寸法を固定するテンプレートではない。

作画の指示を組むときは[プロンプトの組み方](references/art-prompts.md)、HTMLで仕上げるときは[文字組みと表示確認](references/mobile-reader.md)を読む。研究や投稿先の指定がある場合だけ、実例に記載した一次資料や投稿先の最新資料を確認する。

戦闘・アクションのネームや作画では[動きと見せ場のエフェクト](references/art-prompts.md#動きと見せ場のエフェクト)を読み、動きを追えることと「カッケー！！！」と思える主動作を両立する。

日本語の会話コマでは[承認された縦書きの実例](references/vertical-lettering.md)を読み、同梱画像を見る。絵・吹き出し・セリフを一緒に生成した、今回のユーザーが採用した仕上げの基準。絵柄、登場人物、吹き出しの数まで固定する見本ではない。

吹き出しを設計・修正するときは[声と感情に合わせる吹き出し](references/speech-balloons.md)を読む。通常の会話、柔らかな声、疲れた声、叫び、心の声を、輪郭・線の太さ・尾で使い分ける実例を同梱する。

場面が次々に切り替わって追えない、状況が分からない、会話が一画面へ詰まっている、コマの大きさが単調という指摘では[状況をつなぐコマと会話の分解](references/context-and-dialogue.md)を読む。『ゼロブレイク』の原画、8コマへ分けた初稿、ユーザーが採用した大小と枠を使う再改稿を同梱する。文字組みの採用と会話の密度への評価を分け、読者の追加フィードバックで実例を更新する。

縦積みが単調、横並び・斜めのコマ割りも使いたいという依頼では[横並びと斜め枠の使い分け](references/panel-layout.md)を読み、同梱の制作例を見る。短い反応や部品の接写を横へつなぎ、動作には斜めの枠やコマ間を選ぶ。左右寄せだけで横並びを実現したと扱わず、実際の枠と読順をスマホ幅で確認する。

読者視点の制作ガイドを使う、カメラ距離・角度や視線の流れを直す、文字が絵を隠すという依頼では[コマの役割・カメラ・文字の空間](references/reader-perspective.md)を読む。脚本から書き出しまでの判断を分け、引き・寄り・肩越しを理解と感情に合わせて選ぶ。演出上の判断、制作方式の選択、投稿先の仕様をそれぞれ適用する。

絵コンテ・作画・コマ割り・余白の制作や改稿では、レイアウトや生成指示を決める前に、[余白の設計とスクロールの実例](references/scroll-pacing.md)と[人物を描かない余白の採用例](references/whitespace-example.md)を**両方必ず読む**。ユーザーが余白を明示した場合や、音・言葉・視覚演出だけを置くと決めた場合に限定しない。後者は判断の前に読み、人物を描かない間も選択肢に含める。

Markdownのリンクや説明だけで済ませず、同梱の完成画像・修正前後の画像と、番号順の連続窓を画像表示ツールで見る。密に読む区間、待たせる区間、スクロール後に初めて情報が現れる位置を各話のラフへ反映する。制作記録には、読んだ参照・見た画像と、その作品でどの判断を使ったかを短く残す。見本の白地・装甲・区間数をコピーすることや、参照名を記録することだけを適用済みの証拠にしない。企画・設定・脚本だけの依頼には、この画像確認を一律に要求しない。

既存の話を余白で組み直すときは[全編改稿から得た判断と制作例](references/scroll-revision-lessons.md)を読む。コマ・原画・表示単位を分け、余白へ移す文字の重複、表示窓の端からの先出し、全編の因果と配布物の一致まで確認する。

新しい物語を組むとき、主人公への共感や展開の速さを直すとき、セリフが説明調で感情が伝わらないときは[感情と行動の因果](references/emotion-and-causality.md)を読む。異世界転生・強くてニューゲームの実例には、恐怖、力への戸惑い、防御の理由、生還後の反応を含む。物語や山場の数を固定する見本ではない。

称号・報酬・武技名・効果音を作るときや、システム表示の見た目を直すときは[生成文字と作中のシステム表示](references/system-and-lettering.md)を読む。金装飾から機能的な枠、さらに視界内の投影へ変えた実例を同梱する。作中の文字の鮮明さは、その文字を誰がどう見ているかで決める。

効果音を増やす、変身・装甲の装着過程を見せる、能力や装置の仕組みを伝える依頼では[動作の音と装着過程](references/action-sounds-and-transformation.md)を読む。『ゼロブレイク』第1話の制作例を同梱する。音を動作の原因へ置き、部分の変化と動作確認から全身の披露へつなぐ。コマ数や残量表示の形を他作品へ固定しない。

音の持続や広がり、余白の臨場感を設計するときは[コマと余白を跨ぐ音](references/cross-panel-sounds.md)を読み、同梱の修正前後と連続画面を見る。『塔を灯す剣』で採用された、枠を越える衝撃音と白い余白へ減衰する振動音を判断材料にする。

VRMMORPGの操作、武器の働き、主人公の得意分野、大事件の追加を設計・修正するときは[ゲーム操作・装備・得意分野・大事件](references/game-actions-and-incidents.md)を読む。設定、本人の知覚、画面内の作動、次話との接続を揃える。

## 構成を先に決める

ユーザーのテーマ、絵柄、長さ、参照画像、出力先を優先する。テーマを任されているなら、シリーズには長期に事件と人物の選択を生む企画を、短編には視線や移動を縦方向へ自然につなげられる物語を選び、そのまま制作する。

作画前に `storyboard.md` へ各場面の「見せる情報／まだ見せない情報／主人公が分かっていること・感じること・選ぶ行動／カメラの距離と角度／文字と吹き出しの領域／画面の密度／間の役割／次へ目を運ぶもの」を書く。発話者、相手へ求める反応や心の声の目的、口調と息継ぎ、セリフの正確な全文、吹き出しの読む順、縦書きの列分けと、キャラクター・小道具の状態も記録する。

コマを並べる前に、話全体の「密な動作→間→発見→余韻」などの緩急を縦のラフへ置く。余白には位置、待つ理由、直前の手掛かり、次に初めて見せる情報、置く要素（なし・効果音・セリフ・視覚演出など）、地色や背景とのつながり、長さの仮案を記録する。余白の長さは実際の表示高との関係と通読で調整し、全ての間を同じピクセル値や一画面分へ揃えない。重要な待ち時間を省いてよいかを、単なる画像枚数やコマ数で判断しない。

各コマには「読者が今理解する一つのこと／場所・人物の位置・直前の出来事との接続／主に見る人物や対象／画面外にいる人物／次のコマへ持ち越す問いや視線」も残す。接写へ切り替えても同じ場面だと分かる目印を選び、画面外にいることを人物の退場や消失と混同しない。

- **密度**: 近い小コマで動作や焦りを速く読む。大きな顔・枠のない場面・細部の少ない背景で速度を変える。
- **縦の動線**: 雨だれ、足跡、落下、階段、光、視線など、物語に合うものを使う。長い場面には下へ読む理由を持たせる。
- **情報の順序**: 音・セリフ・手・影を先に見せ、必要なら発生源や正体を下に置く。伏せるべき答えは前の作画にも入れない。
- **間**: 発見直前、返事待ち、驚きのあと、見送り後には、次の情報を待つ時間を設計する。広い無言の余白も使い、長い背景をたどる間、音だけが届く間、完全な静けさを場面に合わせて選ぶ。短い動作や会話の密度と組み合わせて読む速度を変える。

余白には、効果音だけ、セリフや心の声だけ、光・影・波紋などの視覚演出だけを置いてよい。人物やコマ枠を毎回描かず、音や声を先に届け、姿や返答を下で見せる選択も使う。セリフだけの余白は通常の人物カット内の会話と区別し、吹き出し・尾の有無を声の届き方に合わせる。話者と読む順を前後でつなぎ、話者を伏せる場合はその意図を記録する。置く位置、反復、薄れ方、次の絵までの距離で時間や感情を作り、空間を埋めるためだけに文字や装飾を増やさない。文字の読みやすさと次の情報の見せ順を保つ。

全部を同じ幅・高さの長方形や正方形に揃えない。絵コンテには各コマの幅、縦横比、左右の配置、枠の有無と、その大きさで何をどう読ませるかも記録する。短い反応を小さく浅いコマへ、状況を把握する場面や受け止める感情を大きなコマへ置くなど、内容に合う大小を選ぶ。枠を外して広がりや余韻を見せる選択もある。変化のためだけに形を変えず、前後のコマとの強弱を設計する。

幅や左右寄せを変えた縦長カードの列だけで、空間を使う構成ができたと扱わない。発話・反応・手元・声が続く場面全体を見て、主役の広い絵、小さな接写、脇に残る空き、枠なしの人物を組み合わせる。問いと答え、動作と結果の順を守り、360/390pxの連続表示で視線と疎密を確認する。具体的な判断は[場面の空間の組み直し](references/panel-layout.md#矩形の列から場面の空間へ組み直す)に従う。

縦スクロールの中にも、短い掛け合いや部位の連続動作を同じ段の横並びへ置ける。これは局所的に速く読むための選択であり、話全体の余白とスクロールの設計を先に行う。日本語漫画では同じ段を右から左、その後に下へ進む読順を基本とし、段ごとの順序を絵コンテへ明記する。斜めは枠線・コマ間そのものへ使い、カメラを傾けるだけで代用しない。文字は正立を保つ。狭いコマは目や手、部品などの接写と短い文字に向き、位置関係、長い会話、全身の披露には広い面積を残す。横並びや斜めも全場面の固定パターンにしない。

「一画面一コマ」「毎回一画面分の余白」も固定しない。小コマでは目や手など対象を絞り、全身や長い会話をそのまま縮小して人物や文字を小さくしない。会話コマの幅を狭めたときも字の読みやすさを保つ。スクロールで大きさ、速度、発見の順序が変わる縦のラフを作り、生成結果が均等なコマ列へ戻っていないか目視する。

見せ順を保護する距離と、感情として待たせる時間を両方確認する。問いと答えが同時に見えなくても、発見がすぐ続いて感じられる場合は、前兆の後や姿が現れる前に間を足す。音を余白へ先に置くと、その発生源を探すスクロールになる。

余白だけの修正では、使える既存の作画を保ち、必要な間の位置から調整する。複数の出来事と返答を一枚の漫画ページへ焼き込んでいる場合、画像の外側へ空白を足すだけでは内部の間や見せ順は変わらない。必要な箇所だけ作画単位を分けるか、原本を保持した表示窓を使い、顔・手・文字・前後の接続を確認する。編集元と採用版を記録し、余白の色、長さ、背景へのつながりを表示幅ごとに確認する。

## 同じ場面をコマで読み進める

場面の切り替えとカメラの切り替えを分ける。新しい場所や出来事へ進む前に、今どこで、誰が何を見て、なぜ次の行動をするのかを読者が追える情報を置く。説明文を増やすだけで済ませず、立ち位置、手の動き、視線、短い問い、聞いた後の反応から不足を補う。空白やコマ数の増加だけを改善の証拠にしない。

カメラの距離と角度はコマの形とは別に選ぶ。引きで位置関係、寄りで感情や手掛かり、肩越しで人物が見ている対象を示すなど、今伝える情報を理由にする。コマを小さくしたから全景も縮める、斜め枠にしたから全てあおりにするという対応へ固定しない。吹き出しの場所をラフで先に確保し、顔・手・伏線と、そこから次へ向かう視線を守る。

会話は一画面へ収めることを目標にせず、発話、相手が受け止める反応、返答を複数のコマへ必要に応じて分ける。同じ場所に留まり、話者の顔、聞き手、話題の物だけを描くコマも使う。登場人物全員と背景全景を毎コマへ入れない。各コマの中心となる理解を決め、密な応酬が効果的な場面はその速さを保つ。一コマ一人、一吹き出し、8コマなどを全作品の固定規則にしない。

## 主人公の理解と感情をつなぐ

能力、本人の知識、感情は別に設計する。最強の身体でも、本人が突然の異世界や自分の力をすぐ受け入れるとは限らない。読者が知る順序を主人公の知覚へ合わせ、感覚、疑い、小さな確認、選択、結果への反応を必要な場面に置く。恐怖や安堵は説明文だけでなく、目、口、手、姿勢、呼吸で見せる。

「展開が速すぎる」という指摘では、飛ばした理解や行動の理由を先に探す。空白を長くするだけでは、なぜ攻撃したか、何に驚いたかは伝わらない。新しい大事件が感情の処理を妨げているなら次話へ送る。勝利や報酬の快感を残しながら、本人が結果を受け止める時間を作る。

アクションは攻撃のきっかけ、身体の動き、結果をつなぐ。前の武器が壊れたなら、次の攻撃手段を絵でも示す。本人の防御や失敗、力加減への戸惑いが必要なら、その表情や接写だけを編集・追加し、使える作画は保つ。

装着や変身そのものを楽しませる場面では、起動から完成形へ飛ばさず、力の発生源、部位の変化、固定や接続、本人が動かせる確認を必要な接写で見せる。全身の決めゴマを後へ残し、動作を短くつなぐ区間と完成前の間を描き分ける。仕組みは作動と反応で伝え、設定にない時間制限・消費量・由来を通知文だけで追加しない。

## 作画と連続性

画像生成を使う場合は、利用可能な `imagegen` スキルを読み、組み込み `image_gen` を使う。絵をHTMLの図形や記号で代用しない。通常の画材や既存作品の編集が指定されている場合はその方法を尊重する。

人物、服装、模様、配色、持ち物などの不変条件と、各場面で変わる状態を分ける。同じ参照画像と共通仕様で各場面を生成する。参照画像の役割は「人物の同一性・絵柄」などと明示し、失敗した旧版のコマ配置を引き継がない。ローカル参照画像は先に表示して確認する。

食事・食べ物が出る場面では、作画前に[食欲が伝わる料理と食事](references/food-art.md)を読む。**美味しそうに見えることを料理作画の品質条件にする。** 料理の形、調理に合う艶・焼き色・柔らかさ・湯気を先に設計し、穀粒・豆・泡などの密集した微細模様で食感を表現しない。調理・配膳・ひと口の献立と器をつなぎ、料理の披露と食べた反応に読む間を残す。スマホ幅で食欲を削ぐ粒の強調や質感がないか目視し、意図的に不味そうな料理を描く場面はその演出を優先する。

連続背景が必要な場面は「一つの枠のない連続画面、上から下へ視点が移る」と指示する。密な連続動作が必要な場面だけ大小の小コマを指示する。作画寸法は場面の役割に合わせ、生成された縦横比に物語全体を従わせない。

日本語の会話コマは、ユーザーが採用した **「絵・吹き出し・セリフを一緒に生成し、セリフは縦書き」** を既定にする。吹き出しを構図へ組み込み、尾は発話者へ向け、顔と手を隠さない。縦書きは正立した文字を上から下へ、列を右から左へ読む。セリフ全文と列の順序を画像生成の指示に含める。横書き・別言語・文字の個別編集などを指定された場合は、その指定を優先する。

**吹き出し・心の声・ナレーション・効果音・作中の通知などの文字は、句読点（「、」「。」と、文の区切りとしてのカンマ・ピリオド）を使わず、意味や息継ぎの区切りで改行して読みやすくする。** 縦書きでは改行を次の縦列への区切りとして指定し、単語の途中や助詞・語尾の一文字だけが独立する位置で分けない。疑問符や感嘆符は、自然な問い、驚き、制止、強い呼びかけや語気を持つセリフへ使ってよい。全話で記号を無くす統一も、毎文へ付ける強制も行わず、記号だけで感情を処理せず表情、反応、手、呼吸、間と合わせる。「…」、長音、括弧、数値や略語の記号も役割に応じて残す。絵コンテと生成指示には使用する疑問符・感嘆符などの記号を含む最終全文と改行・列分けを揃えて渡し、過去の参照画像や実使用指示の表記を新しい文字へ機械的に引き継がない。

ナレーション、効果音、看板、システム通知の組み方は演出に合わせる。会話の縦書きを理由に全ての文字を縦へ固定しない。人物コマへ後から発話を組版する場合は、話者へつながる吹き出しを配置する。余白の声は前後の話者や読む順とつなぎ、人物カットや尾つきの吹き出しを必須にしない。

吹き出しを全て同じ楕円へ揃えず、その発話が誰へ届く声か、声量、感情、呼吸から輪郭、線の太さ・色、尾を選ぶ。静かな会話に叫びのトゲを足すなど、種類を増やすためだけの装飾にしない。話した声と心の声は、口へつながる尾と頭へ続く点などでも区別する。同じ人物の基本の声は一貫させ、感情が変わるところで変える。

選んだ形の輪郭、本文の内側余白、尾の方向、読む順を確認する。トゲや太い線は外側へ収め、文字・顔・手を圧迫しない。楕円をHTMLで作る場合の `border-radius:50%` は通常の丸い会話の出発点に限る。既存作品の横書き・別組版を部分修正するときは、その採用方式を保ち、無関係な全コマの組み直しへ広げない。

生成した称号や効果音は絵の一部として扱う。システムウィンドウなら情報の階層、整列、簡潔な枠を先に決め、視界に浮かぶ表示では透けや文字のにじみも設計する。読めることと、作中で自然に見えることを両方確認する。ぼかしや透過の強さは全作品へ固定しない。

効果音は接触、衣服、歩み、部品の固定など小さな動作にも使い、素材・重さ・速度に合わせて字形、大きさ、色を変える。どのコマの何が鳴るかと正確な語句を指定し、手や顔、セリフを隠さない。強い音だけを連続させず、会話・判断・安堵の静かな区間も読んで強弱を確認する。

「無言」はセリフや心の声がないこと、「無音」は効果音も描かないこととして分ける。絵コンテと生成指示では発話と効果音を別の欄へ記録し、無言の動作コマにも必要な音を指定する。完全な静けさを意図したコマだけ、文字と効果音を禁止する。共通指示の `silent / no text / no writing` が個別の効果音を打ち消していないか、効果音が話者や会話の吹き出しとして渡されていないかを生成前に確認する。具体的な書き分けは[作画指示](references/art-prompts.md)を参照する。

効果音は音源のコマ内だけへ閉じず、複数コマや大きな余白へ続ける演出を積極的に使う。始まり、跨ぐ範囲、減衰と終わる位置を決め、同じ持続音と新しい打撃を区別する。後続コマに新しい音がなくても前の音が続くなら、生成指示で「無音」として打ち消さない。

生成画像ごとに顔、手、小道具の数、受け渡し、衣服、背景、正体の先出しに加え、日本語の全文・指定した句読点と記号が過不足なく入り、意味に沿った改行と列順・吹き出しの話者になっていることを目視で確認する。文字の不具合は、その画像の文字と吹き出しに絞って画像生成ツールで編集し、人物・背景・構図を維持する。元画像を残す。指示どおりの字の大きさが出るとは限らないため、スマホ表示で確認する。

生成した原本を成果物フォルダの `art/` に保存し、実際に使った指示を `PROMPTS.md` に残す。成果物から個人の生成画像キャッシュへ直接依存させない。

原本を保持したまま表示窓で短い動作や接写を分ける場合は、元画像と表示範囲を記録する。CSSの切り出し位置で顔・手・小道具や伏せる情報が変わるため、各窓とつなぎ目を目視する。画像の編集は新しい兄弟ファイルへ保存し、生成指示・編集元・採用ファイルを追えるようにする。

余白へ移したセリフ・心の声・音・通知は、元の絵に同じ文字を残して二重に読ませない。安全な表示窓から外すか、その文字と吹き出し等だけを編集する。原作のコマと、読み手へ順に見せる表示単位を分けて記録し、意図しない欠落・重複・発見順の変更を照合する。

## 文字組み・表示・完成

出力形式の指定がなければ、組版を編集する `index.html` と画像、単独で開ける `reader.html`、縦読み完成画像を作る。画像内のセリフをHTMLにも重ねて二重表示しない。全文と話者は絵コンテに残し、画像の代替テキストにも読める形で含める。画像内の文字はHTMLで個別編集できるとは説明しない。HTMLでは[同梱CSS](assets/reader.css)を必要に応じて使い、色、余白、画像端のつなぎ方を物語へ合わせる。

ブラウザで実際に縦へ読み、少なくとも代表的なスマホ幅で確認する。指定がなければ **390×844 CSS px と360×800 CSS px** が確認の出発点になる。セリフは表示時に19〜20px程度を目安とし、実際の読みやすさを優先する。画像内の文字はCSSのフォント値では測れない。画像の縮小率とスマホ幅の書き出しを見て確認し、画像が読めることをDOMの画像読み込みだけで証明しない。

1. 小さい幅でも顔・手・小道具が分かり、文字がはみ出さない。隠すCSSで横あふれを見逃さない。
2. 動作の密度、長い背景、余韻で読む速度が変わる。主人公の理解・選択・反応と攻撃の原因がつながり、各画像のつなぎ目が唐突な別場面になっていない。
3. 保護したい問いと答えは、スクロールの途中位置でも同時に見えない。表示高と実際の位置で測り、絵の見え始めも目視で確認する。
4. 同一人物と小道具の状態が前後でつながり、最後の情報が前に漏れていない。横並び・高さのずれ・斜め枠でも次のコマを迷わず追え、文字、顔、手が切れていない。
5. 各話の発見前・返事待ち・余韻など、必要な間に意図があり、スクロールで期待や静けさを感じられる。横読みの漫画ページを画像ごとに積んだだけの構成や、全コマの等間隔・一律の大余白は要修正。密な動作と長い間の切り替えを、全長の縮小一覧に加え実際の画面高で通読して確かめる。

画像の読み込み、横幅、文字サイズ、間の用途、必要な見せ順の距離を `validation.json` に記録する。余白のある重要な箇所は、直前の手掛かり・余白内・次の情報の出現を含む連続した画面と、期待や余韻が続くかの通読結果を残す。間を調整した場合は、必要に応じて修正前後の距離や全長も記録する。画面幅はブラウザ設定値だけで判断せず、DOMの `innerWidth/innerHeight` で確認する。ブラウザの拡大率が違う場合は、それも考慮して書き出した画像の寸法を確認する。画像内のコマ割りの確認、スクロール演出の確認、ブラウザ確認の状態を分け、原画の目視だけで全て確認済みとしない。

修正後は、編集元、単独リーダー、完成画像、既存の作品カタログやアプリ同梱版がある場合はそのコピーまで、同じ採用版へ更新する。利用可能な同期・照合手順を使い、同梱確認と実機確認を分けて記録する。表示読み込みの完了を待ってから全長と画像数を測り、修正箇所が周囲の絵・セリフと一緒に見える画面を残す。

HTMLの画像とCSSを一つにまとめるには次を実行する。これは組版ファイルへの埋め込みで、画像の加工ではない。

```bash
python3 <skill-dir>/scripts/package_reader.py <episode-dir>/index.html --output <episode-dir>/reader.html
```

画像とCSSは入力HTMLと同じディレクトリ以下に置く。編集後の再出力では `--force` を付ける。完成画像はブラウザの全体スクリーンショット等で文字を含めて書き出し、冒頭だけでなく最後まで確認する。公開・投稿は依頼されている範囲で行い、投稿用寸法や分割上限は投稿先の最新仕様に合わせる。

最後に、読める成果物を開き、完成した縦読み画像を会話にも表示する。読めるファイル、使用した作画方式、生成指示へのリンクを短く伝える。表示が未確認なら確認済みとは言わない。
