# 本作画より先に見せる構成ネーム

「○○の第○話をネームだけ先に見せて」で使う。通常の新しい話の制作と、構成を組み直す大きな改稿でも本作画の前に使う。この制作環境では、ネームを提示してユーザーの返答を待ってから本作画へ進む。今後の依頼で「見せてそのまま進めて」と明示された場合に限り、提示後に続ける。完成作画を保つ軽微な補修は対象外。

## 先に見せるもの

対象の一話を、白黒の粗い線画と少ない背景で組む。場所と人物の位置、目線、表情、手の動きが分かる程度に描き、仕上げの彩色や細密な衣装は後へ回す。企画の一部だけを試す依頼なら、その範囲を明記する。一部のネームを一話全体の構成確認済みにしない。

構成を判断するため、セリフ全文と列分け、話者、効果音、聞き手の反応、コマの大小、横並びの読順、枠の有無、場面の接続、意図した余白は残す。低解像度でも文字を小さくせず、360/390px幅で読めるようにする。見せたい答えや正体を先のコマへ入れない。

画像生成には `imagegen` と組み込み `image_gen` を使い、粗い人物・ポーズ・構図を生成する。図形や棒人間だけで物語の絵を代用しない。ネームでは修正しやすさのため、文字のないラフ絵へHTMLの吹き出し・文字を重ねてよい。既に文字がある画像へ同じ言葉を重ねない。本作画では、スキル本体の採用済み文字方式へ戻す。

一枚に複数のラフ絵を生成した場合、同じ原本を表示窓で使い、顔・手・後の情報が切り出しから漏れないかを見る。原本は加工せず、表示位置と構成を編集する。

## 作る手順

1. `storyboard.md` から、その話の読む順と「余白／音／接続／感情」を `review/name-preview/plan.json` に移す。原画のための配置図を、完成した読む順の代わりにしない。
2. 同じフォルダの `rough/` に粗い絵を保存する。小さな試作なら `plan.json` と同じ場所でもよい。実行した作画指示・生成元も制作資料へ残す。
3. 同梱の補助ツールで、画像を内包した単独HTMLを出す。
4. 390×844と360×800で縦に読み、全長画像と、重要な間を含む連続画面を保存する。
5. HTMLを開き、全長画像または読める連続画面を会話にも表示する。ネーム先行モードなら、構成への返答を受けてから本作画へ進む。

```bash
python3 <skill-dir>/scripts/build_name_preview.py \
  <episode-dir>/review/name-preview/plan.json \
  --output <episode-dir>/review/name-preview/index.html
```

修正を再出力する場合は `--force` を付ける。ラフの画像バイトは変更せずHTMLへ埋め込む。新しいAPIキーやPythonの追加パッケージは不要で、ラフ絵そのものの生成は画像生成ツールで行う。

## 入力の最小例

```json
{
  "schema": "webtoon-name-preview/v1",
  "title": "第1話の構成ネーム",
  "referenceWidth": 390,
  "beats": [
    {
      "id": "door",
      "type": "panel",
      "image": "rough/door.png",
      "alt": "扉の前で手を止める人物",
      "widthPercent": 90,
      "align": "right",
      "purpose": "扉の音を聞き 相手を止める",
      "dialogue": [
        {"speaker": "主人公", "text": "まだ\n開けないで", "x": 65, "y": 5, "width": 32, "kind": "spoken"}
      ],
      "sounds": [{"text": "カタ…", "x": 15, "y": 80}]
    },
    {"id": "wait", "type": "pause", "height": 230, "purpose": "返事と扉の次の動きを待つ"},
    {"id": "answer", "type": "voice", "speaker": "扉の向こうの声", "text": "開けないで", "height": 220, "purpose": "姿を見せず声だけ届く"}
  ]
}
```

`panel` は絵、`pause` は何も置かない間、`voice` / `sound` は余白へ置く声・音。`height` は390px基準の表示高で、幅に合わせて伸縮する。`x` / `y` / `width` は表示領域に対する百分率。数値を全話へ固定せず、人物と文字の実物を見て決める。

同じ原本の一部を見せる場合は `crop: [x, y, width, height]` を0〜1の範囲で指定する。必要に応じて原本寸法の `imageSize: [width, height]` も渡す。連続する `panel` に同じ `row` と幅を指定すると、JSONの先頭から右→左へ読む同じ段になる。狭いコマには短い反応や接写を選び、全身や長いセリフを縮めて詰めない。セリフの列は `text` の改行で明示し、`tail` は `left` / `right` / `down` / `down-left` で口元に向ける。自動で文を文字数分割しない。

描かない音の理由、発生・継続・確認待ち、人物の意図や隠す本音、接続の理由は `storyboard.md` と各要素の `purpose` へ記録する。プレビューへ出る音がないことと、音の判断を省略したことを混同しない。

## 完成版から分ける

ネームは `review/name-preview/` の制作資料として扱う。完成原稿、カタログ、iOS、公開サーバーへ登録しない。修正後は同じ採用中のネームを更新し、古いネームはGitの履歴へ残す。ネームから仕上げへ進むときは絵コンテを更新し、構成を引き継ぎつつ、原画・文字・表示を改めて確認する。

同梱の[短い試作](name-preview/plan.json)と[プレビューHTML](name-preview/index.html)は、この機能の制作見本であり、既存作品の採用原稿ではない。ラフ絵、セリフ、反応、大小、余白を一緒に読めることを確かめる。未確認のブラウザ・実機や、ユーザーによる構成の採用は未確認として記録する。
