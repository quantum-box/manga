# 本作画より先に見せる構成ネーム

「○○の第○話をネームだけ先に見せて」で使う。通常の新しい話の制作と、構成を組み直す大きな改稿でも本作画の前に使う。この制作環境では、ネームを提示してユーザーの返答を待ってから本作画へ進む。今後の依頼で「見せてそのまま進めて」と明示された場合に限り、提示後に続ける。完成作画を保つ軽微な補修は対象外。

一話全体のネームは、作り始める前に[一話の長さと読み応え](episode-length.md)を読む。幅390 CSS pxで本編高34,000〜60,000 CSS px・内容区間高24,000 CSS px以上・有効80〜120コマという基準、予定量、主筋のまとまりを絵コンテへ残す。補助ツールの `beats` 件数をそのまま有効コマ数にせず、声・音・余白・同じ瞬間の再分割を区別する。一場面だけの試作は対象範囲を明記する。

## 先に見せるもの

対象の一話を、白黒の粗い線画と少ない背景で組む。場所と人物の位置、目線、表情、手の動きが分かる程度に描き、仕上げの彩色や細密な衣装は後へ回す。企画の一部だけを試す依頼なら、その範囲を明記する。一部のネームを一話全体の構成確認済みにしない。

構成を判断するため、セリフ全文と列分け、話者、効果音、聞き手の反応、コマの大小、横並びの読順、枠の有無、場面の接続、意図した余白は残す。低解像度でも文字を小さくせず、360/390px幅で読めるようにする。見せたい答えや正体を先のコマへ入れない。

画像生成には `imagegen` と組み込み `image_gen` を使い、粗い人物・ポーズ・構図を生成する。図形や棒人間だけで物語の絵を代用しない。ネームでは修正しやすさのため、文字のないラフ絵へHTMLの吹き出し・文字を重ねてよい。既に文字がある画像へ同じ言葉を重ねない。本作画では、スキル本体の採用済み文字方式へ戻す。

一枚に複数のラフ絵を生成した場合、同じ原本を表示窓で使い、顔・手・後の情報が切り出しから漏れないかを見る。原本は加工せず、表示位置と構成を編集する。

戦闘・アクションのネームは、配置と作画指示を決める前に[格好よい戦闘をネームから作る](action-direction.md)の採用例を画像で見る。大きな主動作と小さな反応、脇の声、枠抜け、起点から結果へつながるエフェクトを今回の場面へ移し、原画の素材グリッドをそのまま縦へ積まない。

## 作る手順

1. `storyboard.md` から、その話の読む順と「余白／音／接続／感情」を `review/name-preview/plan.json` に移す。原画のための配置図を、完成した読む順の代わりにしない。
2. 同じフォルダの `rough/` に粗い絵を保存する。小さな試作なら `plan.json` と同じ場所でもよい。実行した作画指示・生成元も制作資料へ残す。
3. 同梱の補助ツールで、画像を内包した単独HTMLを出す。
4. 390×844と360×800で縦に読み、全長画像と、重要な間を含む連続画面を保存する。一話全体なら有効コマ数・本編高・純余白・内容区間高を計測し、量・物語・水増しを判定する。UIと構成メモを本編の高さへ含めず、不足を脚本へ戻して補う。
5. HTMLを開き、全長画像または読める連続画面を会話にも表示する。対象範囲、390px幅での本編高・内容区間高・有効コマ数の目標と実量を短く伝える。構成への返答を受けてから本作画へ進む。

```bash
python3 <skill-dir>/scripts/build_name_preview.py \
  <episode-dir>/review/name-preview/plan.json \
  --output <episode-dir>/review/name-preview/index.html
```

修正を再出力する場合は `--force` を付ける。ラフの画像バイトは変更せずHTMLへ埋め込む。新しいAPIキーやPythonの追加パッケージは不要で、ラフ絵そのものの生成は画像生成ツールで行う。

HTMLの末尾で「構成計測」を開くと、画像とフォントの読み込み後の読書領域幅・本編高・明示的な `pause` 高・表示カット数・DPR・画像失敗数を見られる。広い画面でも `referenceWidth`（既定390px）で表示する。基準の390px幅で測り、360px幅の実測を390pxの値と取り違えない。表示カット数は有効コマ数ではなく、明示した余白だけを除いた高も内容区間高の確定値ではない。他のCSS空白や画像内の大きな無情報の空白帯は別途確認する。UIは整数へ丸め、未丸めの計測値は `#preview-measurement` の `data-metrics` にJSONで残す。読了時間は必要な場合の任意の補助情報にとどめる。

## 入力の最小例

```json
{
  "schema": "webtoon-name-preview/v1",
  "title": "第1話の構成ネーム",
  "referenceWidth": 390,
  "beats": [
    {
      "id": "door",
      "type": "panel",
      "image": "rough/door.png",
      "alt": "扉の前で手を止める人物",
      "widthPercent": 90,
      "align": "right",
      "purpose": "扉の音を聞き 相手を止める",
      "dialogue": [
        {"speaker": "主人公", "text": "まだ\n開けないで", "x": 65, "y": 5, "width": 32, "kind": "spoken"}
      ],
      "sounds": [{"text": "カタ…", "x": 15, "y": 80}]
    },
    {"id": "wait", "type": "pause", "height": 230, "purpose": "返事と扉の次の動きを待つ"},
    {"id": "answer", "type": "voice", "speaker": "扉の向こうの声", "text": "開けないで", "height": 220, "purpose": "姿を見せず声だけ届く"}
  ]
}
```

`panel` は絵、`pause` は何も置かない間、`voice` / `sound` は余白へ置く声・音。`height` は390px基準の表示高で、幅に合わせて伸縮する。`x` / `y` / `width` は表示領域に対する百分率。数値を全話へ固定せず、人物と文字の実物を見て決める。

同じ原本の一部を見せる場合は `crop: [x, y, width, height]` を0〜1の範囲で指定する。必要に応じて原本寸法の `imageSize: [width, height]` も渡す。連続する `panel` に同じ `row` と幅を指定すると、JSONの先頭から右→左へ読む同じ段になる。狭いコマには短い反応や接写を選び、全身や長いセリフを縮めて詰めない。セリフの列は `text` の改行で明示し、`tail` は `left` / `right` / `down` / `down-left` で口元に向ける。自動で文を文字数分割しない。

縦長カードの積み重ねが単調な場合は、[場面の空間を組み直す判断](panel-layout.md#矩形の列から場面の空間へ組み直す)を使う。連続する `panel` / `voice` / `sound` に同じ `composition` を付けると、一つの相対配置の空間になる。`offsetX` は左端の百分率、`offsetY` は390px幅基準の上からの距離、`widthPercent` は読書幅に対する幅。高さは各要素の位置と自然高から計算される。読む順はJSON順に残し、重なる範囲と実際の見せ順を画面で確認する。`pause` や `row` との併用、途切れたグループの再登場はできない。

`frame: "none"` / `"thin"` で表示窓の枠を選べる。原画自体に枠が描かれている場合、`none` だけではその線は消えない。顔や手を守った表示窓を選ぶか、必要な素材を描き直す。声や音の `widthPercent` も指定できるため、広い絵の脇の余白へ置ける。配置のために文字を縮めず、セリフは読書領域を基準とする19〜22pxを保つ。

相対配置の中に空の縦帯が残る場合は、その帯も純余白へ含める。声の要素内の空きと絵が同じ高さに重なる場合は、絵のある区間まで純余白にしない。各要素の実際の占有区間を重ね合わせ、空の帯は一度だけ数える。画像の大きな無情報帯も別途目視し、背景が白いだけの人物や演技まで除外しない。

描かない音の理由、発生・継続・確認待ち、人物の意図や隠す本音、接続の理由は `storyboard.md` と各要素の `purpose` へ記録する。プレビューへ出る音がないことと、音の判断を省略したことを混同しない。

## 完成版から分ける

ネームは `review/name-preview/` の制作資料として扱う。完成原稿、カタログ、iOS、公開サーバーへ登録しない。修正後は同じ採用中のネームを更新し、古いネームはGitの履歴へ残す。ネームから仕上げへ進むときは絵コンテを更新し、構成を引き継ぎつつ、原画・文字・表示を改めて確認する。

同梱の[一話全体の試作](name-preview/plan.json)と[プレビューHTML](name-preview/index.html)は、この機能の制作見本であり、既存作品の採用原稿ではない。[設計と実測](name-preview/README.md)には80コマの主筋、余白の登録、スマホ幅での確認を記録している。ラフ絵、セリフ、反応、大小、余白を一緒に読んで構成を確かめる。未確認のブラウザ・実機や、ユーザーによる構成の採用は未確認として記録する。

戦闘の空間配置を確認する場合は[『橋上の一歩』の部分試作](action-name-preview/README.md)と[ネーム](action-name-preview/index.html)も参照する。24コマの戦闘一場面であり、一話全体の分量基準の採用例ではない。広い槍の軌道、ずらした接写、剣の落下と回収、跳躍前の選択、反撃後の無音を組む。主動作では原画に描いた斜めの枠を武器と身体が突き抜け、効果音も白い枠外へ広げる。2026-10-09にコマ配置と戦闘エフェクトの方向をユーザーが採用した。

この試作では評価されたコマ配置を保ち、エフェクトを強めた。動きを示す場合は発生源、軌道、結果をつなぎ、薙ぎ払い、踏み切り、武器の接触を別の線と帯で描き分ける。人物と武器を複製せず、顔、握り手、一本の武器を読めるままにする。今後は[動きと見せ場のエフェクト](art-prompts.md#動きと見せ場のエフェクト)を使い、理解できる動作と格好よい主動作を両立する。採用の範囲はこの部分試作の演出方向で、本作画と公開は未着手。
