# 状況をつなぐコマと会話の分解

展開を追えない、場面の切り替わりが多い、状況の説明が足りない、会話が一画面へ詰まっているという指摘で使う。『ゼロブレイク』への2026-10-06のフィードバックを起点にする。

ユーザーの指摘は、絵の場面が次々に変わって内容を掴めないこと、コンテキストの不足、毎コマに場面の全要素を描く必要はないこと、会話を複数のコマで少しずつ進めること。画像の読み込みや文字の検査が通っても、読者が物語を追えることは証明できない。

## 状況を足す場所を見つける

読者がその時点で知っている情報だけで、場所、人物の関係、直前の出来事、今の目的、行動の理由を辿れるか確認する。シリーズ設定資料に書いてあることを、読者が既に知っていると扱わない。必要な背景は今の選択を理解できるところまで見せ、世界設定を一度に説明しない。

カメラが変わるだけなら、同じ場所の印、目線、手元、姿勢などをつなぐ。場所や時間そのものが変わるなら、移動、経過、きっかけを必要な分だけ挟む。同じ背景を繰り返すだけでも、接写を並べるだけでも接続の代わりにはならない。

| 引っかかり | 足す・分けるもの | 改善の判断 |
| --- | --- | --- |
| 危機の後すぐ普通の会話になる | 着地した場所、身体を支える動作、安全の確認 | 助かった直後の会話だと絵で分かる |
| 初対面で複数の設定を一息に話す | 礼、名乗り、身分の説明と聞き手の反応 | 今知ったことが次の反応へつながる |
| 何かを見た直後に大きな行動をする | 見た対象、ためらい・判断、動き出すきっかけ | 誰が何に反応して動いたか辿れる |

## 一つの会話に留まり、焦点を移す

読者が一コマで主に理解することを決める。「礼を聞く」「名を知る」「身分を知る」「驚く」「返事をする」は分けられる。吹き出しを分割するだけでなく、聞いた表情や手の変化を必要な位置に挟む。コマが増えても、絵が伝える新しい理解がなければ冗長になる。

位置関係を一度見せた後は、話す人、聞く人、話題の物へ寄れる。画面外の相手は同じ場所にいる。話者の方向と視線を保ち、画面外の発話の尾を物へ向けない。全員を毎回登場させず、必要な場所で二人や全景へ戻る。

「一コマ一人」「一コマ一吹き出し」は固定しない。短い掛け合い、同時の反応、位置関係が重要な動作には複数人や複数の発話が適する。会話を一画面へ収めることや、一コマを必ず一画面にすることを目標にしない。

## 実例：救出後の自己紹介

**状態：大小と枠を使う再改稿を、2026-10-06にユーザーが「めちゃくちゃ良いぞ！」と評価し、採用例として記録。** 評価対象は救出後の会話8コマの改稿例。第1話全体や公開版の差し替えではない。元の縦書きの方式は保ち、同じ会話の見せ方を比較する。

元の箇所は `examples/zero-break/v5/manifest.json` の `safe`、原画は `art/11-safe.png`。前に `landing`、後に `approach` がある。[同梱の修正前原画](zero-break/before-safe.png)で確認する。

修正前は一枚にミラとレン、二人の会話、細かい街の背景がある。ミラは「ありがとう。私はミラ。この国の王女よ。」、レンは「レンだ。無事なら、それで。」と話す。礼、名前、身分、返事まで同時に提示され、王女という新情報をレンが受け止める間がない。

[比較リーダー](zero-break/index.html)を開き、[前半4コマ](zero-break/after-01.png)と[後半4コマ](zero-break/after-02.png)を画像表示ツールでも見る。8コマは今回の試作上の選択であり、今後のコマ数の目標ではない。二枚の画像ファイルに4コマずつ入っているため、画像枚数とコマ数も区別する。

| コマ | 主に見せる対象 | 今理解すること・文字 | 前後との接続 |
| --- | --- | --- | --- |
| 1 | 一度だけ二人と足元 | 二人は同じ荷物用の天幕の跡で生きている。無言 | 破れた布、荷物、レンの支える素手、ミラの接地で着地後の安全を示す |
| 2 | ミラの顔 | 「ありがとう。」 | 左下のレンへ視線。背景の布を残す |
| 3 | レンの顔 | 礼を聞いて安堵する。無言 | 同じ低い姿勢から右上のミラを見る |
| 4 | ミラの顔と胸元の手 | 「私はミラ。」 | 同じ目線のまま自分を指し示す |
| 5 | ミラの手と同じ服・宝石 | 「この国の王女よ。」 | 4の手元へ寄る。画面外の口の方向へ尾を向ける |
| 6 | レンの顔 | 王女だと知って小さく驚く。無言 | 視線を右上へ保つ。新しい場面や行動を足さない |
| 7 | レンの顔と自分を示す手 | 「レンだ。」 | 驚きを受け止めてから名乗る |
| 8 | レンの上半身と休めた手 | 「無事なら、それで。」 | 低い姿勢、赤いマフラー、破れた布を保ち、返答の後に余韻を置く |

セリフ全文は修正前と同じ。新しい事件や人物は足さず、同じ場所に留まる。王女という説明の接写に王冠の紋章を足すと、後の `fragment` で初めて出す手掛かりが漏れるため、この試作では元からある服と宝石だけを使う。画像生成の参照は人物と絵柄の保持に使い、元の会話密度をコピーしない。

[前半の実行指示](zero-break/prompt-01.txt)、[後半の実行指示](zero-break/prompt-02.txt)、[生成の出所](zero-break/generation.json)、[表示・目視の確認記録](zero-break/validation.json)を残す。組み込み `image_gen` で絵・吹き出し・縦書きセリフを一緒に生成し、HTMLの重複文字は置かない。

2026-10-06、390×844と360×800 CSS pxで画像の読み込み、横あふれ、修正前後の切り替えを確認した。[360px幅の改稿試作](zero-break/after-360.png)と[390px幅の改稿試作](zero-break/after-390.png)で、セリフ全文、縦列の順、無言の反応、目線と衣服の接続を目視した。作画自体は724×2172pxの画像2枚で、360px表示では各1080px、390px表示では各1170pxになる。会話全体が一画面に収まらない構成を確認できるが、長さだけで読み心地の成功とは扱わない。

## 追加の指摘：コマの大きさと枠を使う

同日、ユーザーは「ワクの大きさとかも効果的に使って欲しい」「全部同じサイズにしたくない」と指摘した。最初の8コマは会話の分割を実現したが、ほぼ全幅の矩形が続き、コマの面積や形による強弱が弱かった。この初稿を完成した構成の基準にはしない。

再改稿では同じ8コマと同じセリフを保ち、幅、高さ、左右の配置、枠の有無を変えた。[前半](zero-break/varied-01.png)と[後半](zero-break/varied-02.png)を表示し、[比較リーダー](zero-break/index.html)で最初の8コマとも比べる。形を変える目的は、そのコマで何をどう読ませるかを明確にすること。ランダムな大小や大小交互の模様を目標にしない。

| コマ | 今回の枠・大きさ | その選択の役割 |
| --- | --- | --- |
| 1：安全確認 | ほぼ全幅の大コマ | 二人の位置と足元を一緒に把握する |
| 2：礼 | 幅を絞った右寄せのコマ | ミラの言葉と顔へ焦点を移す |
| 3：安堵 | 左寄せの小さく浅い横長コマ | レンの目元だけで短い聞き手の反応を読む |
| 4：ミラの名乗り | 広く縦長の大コマ | 顔と胸元の手で初対面の名乗りを受け止める |
| 5：身分 | 中くらいの横長の手元 | 直前の手と服に留まり、王女という情報を聞く |
| 6：驚き | 左寄せの浅い横長コマ | 目元の変化を短く拾う |
| 7：レンの名乗り | 右寄せの中くらいの縦長コマ | 返答へ戻り、本人の顔と自分を示す手を見せる |
| 8：安堵の返事 | 全幅の大きな枠なしの画面 | 落ち着いた返事と身体の力が抜けた余韻を残す |

小さくした反応コマは全身を縮めず、目元へ描き直した。会話コマは字が読める幅を保ち、人物や文字を押し潰して形を変えていない。大小だけで時間が決まると扱わず、情報量、表情、余白、次のコマとの関係も読む。今回の配置、比率、枠なしの最後を全作品へ固定しない。

この採用例は大小と左右寄せの基準であり、同じ段へコマを横並びに置く例とは分ける。後の「縦にスタックするだけでなく、必要な状況で横や斜めも使いたい」という指摘は、[横並びと斜め枠の制作例](panel-layout.md)へ反映した。後の制作例へのユーザー評価を、この採用例の評価から推定しない。

[前半の再改稿指示](zero-break/prompt-varied-01.txt)と[後半の再改稿指示](zero-break/prompt-varied-02.txt)には各コマの相対的な幅と高さを明記した。「大小をつける」だけの指示で均等なコマ列が出たら、役割と形を具体化して直す。生成の出所と確認結果は既存の記録へ追記し、初稿も残す。再改稿はユーザーの肯定的な評価を受け、コマの大小と枠を使う採用例になった。

再改稿は390×844と360×800 CSS pxで表示と比較の切り替えを確認し、[360px表示](zero-break/varied-360.png)と[390px表示](zero-break/varied-390.png)で文字、目元、小コマと大コマの差、読順を目視した。幅を狭めた礼と名乗りのコマもセリフを読める。表示確認と、その後のユーザー評価を[記録](zero-break/validation.json)で分けている。

## スマホで確かめる五つのこと

1. コマ1だけで、二人がどこにいて、直前の危機からどう助かったかを辿れる。
2. 顔や手へ接写しても、場面が移ったと誤解しない。視線、姿勢、服、布の状態が前後でつながる。
3. 「ありがとう」への安堵と、「王女」への反応が別の瞬間に見え、返事が説明を受けた後に来る。
4. 字が読めるだけでなく、一コマの発話・対象・理解を追える。小さな目元も分かり、狭い会話コマの文字も読める。大小、左右の配置、枠なしの場面でも読順が崩れない。
5. 最後まで連続して読み、前半で聞いたことを受け止めてから後半へ進める。長くなっただけでなく、理解が増えたか確認する。

390×844と360×800は表示確認の出発点。字の読みやすさ、内容の接続、コマ密度、読者からの評価を別々に記録する。試作に対するユーザー評価がない段階で「採用済み」「読み心地が改善した」と確定しない。

## フィードバックを実例で更新する

### 第1〜10話へ展開した改稿例

同日の context-dialogue-v6 改稿は、作画済みの第1〜10話を196画像・317コマへ組み直した。新規生成54素材と、承認例の再利用3素材を使い、旧原画は保持した。全50話の脚本にもコマ別の指示を反映したが、第11〜50話の作画は未制作。この改稿全体へのユーザー評価はまだ記録していない。8コマの承認を全10話の承認へ広げない。

| 実際に足した・直したもの | 次の制作で判断すること |
| --- | --- |
| 第1話で騎士がルークと名乗り、第4話でミラが整備士ノアを紹介 | 制作資料にある名前や役割を、初登場の読者が知っていると扱わない |
| 第1話の暴走場面で、上の橋・レンの低い足場・その下の天幕を先に見せた | 会話の接写を増やすときも、行動に必要な上下・安全側の説明を省かない |
| 第6話の梯子固定→一人ずつ避難→17人確認→空の車両を放す順 | 小道具や人数の確認コマは、次の動作を正当化する位置へ置く |
| 第8話の初代英雄像の星を金へ修正。レンの核は青のまま | 同じ形を比較する場面でも、同じ色や同一物として描かない。部分編集の前後も連続性を確認する |
| 第9話は夜と呼吸器の隔離回路を保持 | 説明用の接写や青い光で、後のフォームや都市全体の復旧を先に見せない |

この回の確認は原画と360/390px幅のネイティブ画像書き出しを使った。HTMLのブラウザ再確認と実機確認は未実施。書き出し方式、確認範囲、未確認の項目を分け、以前のブラウザ記録で改稿版を確認済みにしない。

リポジトリ内の `examples/zero-break/production/feedback-v6/records` に実行指示・参照のハッシュ・修正前後、`baseline` に旧構成、`artifact-verification.json` に原画・単体リーダー・ZIP・iOS同梱版の照合を残す。原画の保存、配布物の一致、読み心地への評価はそれぞれ別の証拠で管理する。

次の指摘では、この記録に同じ失敗が残っているか確認し、該当する連続区間を小さく直す。修正前、指摘、改稿の狙い、修正後、確認結果をセットで残す。今回の型へ機械的に寄せず、何が読者の理解を妨げたかから判断する。

ユーザーが試作を評価したら、どの部分への評価かを記録する。縦書きの評価を会話密度の承認へ広げない。未確認・修正待ち・暫定採用・採用を区別し、同じ課題への後の指摘があれば古い見本の適用範囲を更新する。汎用の判断基準はスキル本体に短く残し、作品固有のセリフやコマ数はこの実例に置く。
