# 余白の設計とスクロールの実例

全話の縦ラフを作るときに使う。2026-10-07、ユーザーは『ゼロブレイク』第2〜10話の改稿版に「横読み漫画と一緒すぎる」「コマをスタックするだけじゃなく余白を効果的に使う」と指摘した。横並びや斜め枠の作画ができたことを、縦スクロール演出の完成・承認と扱わない。

## コマを並べる前に、読む時間を決める

話全体の緩急を縦ラフへ置き、各区間で読者が何を待ち、次に何を見つけるかを決める。短い動作の密度と、受け止める時間・発見前の待ち・終わった後の余韻を組み合わせる。余白は静かな場面だけの飾りではなく、次の情報へ進むまでの読書体験として設計する。

| 役割 | 直前の手掛かりと次の情報 | 余白の選び方 |
| --- | --- | --- |
| 呼吸・感情を受け止める | 発話や衝撃→聞き手の反応 | 短い無言の間。小さな表情や手元を置く選択もある |
| 緊張・発見を待たせる | 音、影、問い→発生源や答え | 広い余白と、下で初めて分かる情報。答えを前の原画へ入れない |
| 距離や視点の移動 | 見上げる／見下ろす視線→目的地 | 空、落下、階段、光などの連続背景をたどり、情報を疎にする |
| 場面・時間の移行 | 今の場面の終わり→次の場所の把握 | 地色や背景端からつなぐ間。移行後の場所・人物を明示する |
| 余韻 | 結果や見送り→次の行動 | 結果を受け止める時間を残す。すぐ別の大事件を詰めない |

`storyboard.md` の必要な間には「位置／役割／直前の手掛かり／次に初めて出す情報／置く要素／地色・背景／長さの仮案」を残す。長さは表示高との関係をラフの出発点にし、実際にスクロールして決める。固定の比率、余白率、コマ数、毎回一画面の空白を合格基準にしない。全ての会話を離すと応酬が遅くなり、救出中の位置関係を切ると因果が途切れるので、必要な区間の密度は保つ。

横並びは短い反応や接写を一息に読む局所的な選択。発話→返事待ち→返答、前兆→出現、装着→完成披露を同じ画像や同じ段へ詰め、読者が同時に答えを見てしまう場合は、作画単位から見直す。完成した漫画ページの画像間に長い空白を足しても、画像内部の時間と見せ順は変わらない。

## 余白の中を何で読むか

余白に人物や背景の説明を必ず入れる必要はない。2026-10-07の追加フィードバックに沿い、次の表現を作画・組版の選択肢として使う。

| 置く要素 | 例 | 読者に起こすこと |
| --- | --- | --- |
| 効果音だけ | 離れた位置に「どくん」、下へ続く足音、装甲の「カチッ」 | 姿のない相手、接近する距離、固定された瞬間を音から感じる |
| セリフ・心の声だけ | 余白に「……聞こえる？」や短い独白を置き、返答や表情は下へ残す | 声に耳を澄ませる、言葉を受け止める、返事を待つ |
| 視覚演出だけ | 一筋の光、揺れる影、波紋、雨、徐々に薄れる軌跡 | 視線を下へ運ぶ、時間や感情の変化をたどる |
| 何も置かない | 地色だけの静かな区間 | 不在、沈黙、ためらい、余韻を感じる |

役割に合わせて選び、必要なら組み合わせる。毎回全種類を使わず、余白を埋めるためだけに足さない。縦の位置、反復の間隔、字の大きさ、濃淡、次の絵までの距離を設計し、文字を小さくしたり読めないほど薄くしたりして広さを作らない。

セリフだけを置く場合は、話者・発話か心の声か・読む順を絵コンテに残し、前後の人物や声の表現とつなぐ。話者の正体を意図して伏せることもできる。人物カットや尾つきの吹き出しを必ず追加する規則にせず、声の届き方で輪郭・尾・枠なしの文字を選ぶ。元の画像にある同じセリフを再掲して二重に読ませない。

次の情報が文字や視覚演出から先に漏れていないか、途中の表示位置でも確認する。間の中へ新しい情報を置いたら、その情報から次の発見までの距離と読む時間を測り直す。

## 作画単位と表示単位を合わせる

一枚を複数コマにするのは、密に続けて読む区間が合うときに選ぶ。間を挟む前後の情報は別の素材にするか、原本を保持した表示窓と用途を記録する。既存素材で安全に分けられない場合は、その場面だけ描き直す。文字や手を横切る自動切り出し、余白を確保するための全景と文字の一律縮小を行わない。

画像の内側に余白を描く場合は、静かな地色・情報の少ない背景・フェード端を作画指示へ明記する。画像の外側に置く場合は、リーダーの `.pause` などで位置と長さを別に調整し、完成画像・単体HTML・アプリ同梱版にも同じ間を出力する。余白を一律のCSS `gap` に任せない。

## 間に役割を持たせる

| 場面 | 待つ理由 | 使った間 |
| --- | --- | --- |
| ランプへの気づき | 異変を受け止める | 密な操作コマのあとに短い呼吸 |
| 信号から子の発見 | 光の発生源を探す | 長い宇宙の背景と、発見直前の広い余白 |
| 子を見つけたあと | 返事を待ち、耳を澄ませる | 無言の暗がり |
| 巨大な親が現れる前 | 姿の見えない相手を待つ | 暗がりに「どくん」が先に届き、さらに下で姿が現れる |
| 見送りから最後の記録 | 去った相手の余韻を残す | 記録の前と「異常なし」の前に別々の長さの間 |

広い空白は、それ自体が静かな時間になる。直前に問い、音、視線などを置き、読者が何を待っているか分かるようにする。後へ読む理由がある場面では、空の画面も演出として成立する。物語に合わせて地の色や背景端をつなげる。

操作や反応の小コマは近いまま読み、発見や余韻で長く待つ。ユーザーが間を求めた場合には、発見直前・返事待ち・見送り後のどこが短いかから見直す。

## 見せ順と待ち時間を分けて考える

修正前も、問いと答えは確認したスマホ表示では同時に見えなかった。今回の要望では、そこからさらに待つ時間を広げた。

390×844 CSS pxでの実測:

| 距離 | 修正前 | 修正後 |
| --- | ---: | ---: |
| 「救難信号？」の末尾→子の場面 | 909px（約1.08画面） | 1263px（約1.50画面） |
| 「返事が……下から。」の末尾→親が見え始める位置 | 921px（約1.09画面） | 1545px（約1.83画面） |

修正後は「どくん」の末尾から親の出現位置まで926px。360×800では、上記の二つが1164px・1428px、鼓動から親まで854pxだった。

返事を待つ無言の余白は390px幅で429px、親の出現前の暗がりは624px。全長は5188pxから7312pxへ変わった。これらは今回の物語と表示範囲で選んだ値で、全作品の最小値や目標ではない。完成画像は390×7311px。

同時に見えない距離を確認したら、さらにスクロールして期待や静けさが残るかを読む。全長の増加や画面数だけで良し悪しを決めない。

## 採用前にスクロール体験を確認する

全長を縮めた一覧では密度の分布、実際の画面高では待ちと出現を確認する。重要な間は「手掛かりが見える→余白をたどる→答えが初めて見える」の連続した表示を残す。答えが出る前の途中位置も見る。距離の計算が合っていても、全身の姿や影、セリフで答えが先に漏れていないかを確認する。

`validation.json` には間の目的、手掛かりと答えの位置、確認した幅・表示高、連続画面、待ち時間の通読結果を記録する。余白はあるが何を待つか分からない、全コマが等間隔、横読みページのまとまりが途切れず続く場合は要修正。原画の読みやすさ、ネイティブの画面窓、実際のブラウザ・実機の状態を別々に記録する。確認ができていない部分は未確認とする。

## HTMLで調整する

既存の絵を使える修正では、画像を再生成せず、場面間の余白、独立した無言の区間、音の位置から調整する。同梱CSSの `.pause` は、各要素の `--pause` を指定した場所だけ高さを持つ。

以下の数値はSF実例の構成に近い例。色・位置・長さは、その物語の間に合わせて変える。

```html
<div class="pause" style="--pause:clamp(320px,110cqw,528px)"
     aria-hidden="true"></div>

<div class="pause" style="--pause:clamp(460px,160cqw,768px)">
  <p class="sound" id="approaching-sound" style="top:22%;left:43%">どくん</p>
</div>
```

DOMで測る場合、音や問いの下端と、次の絵の識別できる情報が見え始める位置を使う。絵の途中で正体が現れるなら、その位置を目視で決める。人物や物体の最初の見え方が変わるため、画像の上端だけで判定しない。

修正前を残し、間の用途、実際の表示範囲、問いや音から答えまでの距離を記録する。小さい幅で文字が読めるかと、密な動作から長い間へ切り替わるリズムを、冒頭から最後まで確認する。
