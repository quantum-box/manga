# 間とスクロールの実例

2026-10-04、ユーザーの「もっと余白を広く取ったりしてスクロールさせるようにして、間をうまく使って」という要望を『星を拾う夜』v2へ反映した。絵とセリフは同じ6場面を使い、余白と効果音の位置を調整した。

[修正前](spacious-before.jpg)と[修正後](spacious-after.jpg)を画像表示ツールで比較する。全体では密度と間の配置を見て、文字や発見の順序はスマホ幅の各部分で確認する。元の作業場所は `/Users/takanorifukuyama/git/manga/examples/star-lighthouse/webtoon-v2/`。この場所がなくても同梱画像で比較できる。

## 間に役割を持たせる

| 場面 | 待つ理由 | 使った間 |
| --- | --- | --- |
| ランプへの気づき | 異変を受け止める | 密な操作コマのあとに短い呼吸 |
| 信号から子の発見 | 光の発生源を探す | 長い宇宙の背景と、発見直前の広い余白 |
| 子を見つけたあと | 返事を待ち、耳を澄ませる | 無言の暗がり |
| 巨大な親が現れる前 | 姿の見えない相手を待つ | 暗がりに「どくん」が先に届き、さらに下で姿が現れる |
| 見送りから最後の記録 | 去った相手の余韻を残す | 記録の前と「異常なし」の前に別々の長さの間 |

広い空白は、それ自体が静かな時間になる。直前に問い、音、視線などを置き、読者が何を待っているか分かるようにする。後へ読む理由がある場面では、空の画面も演出として成立する。物語に合わせて地の色や背景端をつなげる。

操作や反応の小コマは近いまま読み、発見や余韻で長く待つ。ユーザーが間を求めた場合には、発見直前・返事待ち・見送り後のどこが短いかから見直す。

## 見せ順と待ち時間を分けて考える

修正前も、問いと答えは確認したスマホ表示では同時に見えなかった。今回の要望では、そこからさらに待つ時間を広げた。

390×844 CSS pxでの実測:

| 距離 | 修正前 | 修正後 |
| --- | ---: | ---: |
| 「救難信号？」の末尾→子の場面 | 909px（約1.08画面） | 1263px（約1.50画面） |
| 「返事が……下から。」の末尾→親が見え始める位置 | 921px（約1.09画面） | 1545px（約1.83画面） |

修正後は「どくん」の末尾から親の出現位置まで926px。360×800では、上記の二つが1164px・1428px、鼓動から親まで854pxだった。

返事を待つ無言の余白は390px幅で429px、親の出現前の暗がりは624px。全長は5188pxから7312pxへ変わった。これらは今回の物語と表示範囲で選んだ値で、全作品の最小値や目標ではない。完成画像は390×7311px。

同時に見えない距離を確認したら、さらにスクロールして期待や静けさが残るかを読む。全長の増加や画面数だけで良し悪しを決めない。

## HTMLで調整する

既存の絵を使える修正では、画像を再生成せず、場面間の余白、独立した無言の区間、音の位置から調整する。同梱CSSの `.pause` は、各要素の `--pause` を指定した場所だけ高さを持つ。

以下の数値はSF実例の構成に近い例。色・位置・長さは、その物語の間に合わせて変える。

```html
<div class="pause" style="--pause:clamp(320px,110cqw,528px)"
     aria-hidden="true"></div>

<div class="pause" style="--pause:clamp(460px,160cqw,768px)">
  <p class="sound" id="approaching-sound" style="top:22%;left:43%">どくん</p>
</div>
```

DOMで測る場合、音や問いの下端と、次の絵の識別できる情報が見え始める位置を使う。絵の途中で正体が現れるなら、その位置を目視で決める。人物や物体の最初の見え方が変わるため、画像の上端だけで判定しない。

修正前を残し、間の用途、実際の表示範囲、問いや音から答えまでの距離を記録する。小さい幅で文字が読めるかと、密な動作から長い間へ切り替わるリズムを、冒頭から最後まで確認する。
