# 一話の長さと読み応え

通常の一話は、**8〜12分くらい楽しめる長めの分量**を目標にする。これは2026-10-08のユーザー指定に基づく制作基準で、業界共通の規格ではない。新しい話の脚本・ネームと、構成を組み直す改稿で使う。既存の公開話を、このルール追加だけで一括改稿しない。

過去の制作資料にある4〜6分、26〜30画面、少数の表示窓などは新基準より前の履歴で、今後の通常話の目安ではない。通常話の制作依頼は一話全体を対象とし、長さの記録に `scope: full_episode` を残す。未記入を一場面の試作と解釈して範囲を縮めない。

## 長さを三つに分けて定義する

| 指標 | 定義 | 通常話の初期目安 |
| --- | --- | --- |
| 読了時間 | 新しい本編を、絵・全文・表情・動作を追って自然に読む時間。操作説明、放置、制作レビューの中断は除く | 8〜12分を目標。未計測の時間は達成済みにしない |
| 有効コマ数 | 絵がある独立したコマ・枠のないカットのうち、新しい動き、理解、選択、結果、感情や関係の変化を読むもの | 80〜120コマを設計の目安にする |
| 本編の画面相当数 | 390×844 CSS pxで、本編の最初の要素の上端から最後の要素の下端までの高さを844で割る。重複する確認画像の枚数ではない | 40〜70画面相当を配置の目安にする |

数字同士を換算しない。80コマや40画面が自動的に8分になるわけではない。初回の長いネームで量と実際の読み心地を確かめ、その作品に必要な量を補正する。上限に近づいたら反応や結果を削って切るのではなく、話の区切りと密度を見直す。

12分・120有効コマ・70画面は厳密な上限ではない。超えた場合は過密・冗長性・一話の区切りを見直し、必要な結果や反応を切って機械的に分割しない。

生成画像の枚数、画像ファイルの分割数、DOM要素数は有効コマ数ではない。一枚の原画に複数の独立した出来事があればそれぞれ数えられるが、同じ静止画を切り出しただけ、同じ瞬間の寄り引きだけでは増やさない。接写が新しい手掛かりや感情を見せる場合は、その理解を絵コンテへ書いて数える。

余白の声・音は別の読書要素として残す。新しい発見や返答なら物語の進みに含めるが、絵の有効コマ数へは加算しない。一つのセリフを多数の余白へ分けたこと、同じ音の反復、待ち時間だけで分量基準を満たさない。セリフの文字数は参考値として扱い、無言のアクションや静かな回へ文字の下限を強制しない。

数えるコマは、絵コンテの既存一覧へID・場面・読者が新しく理解することの一文を対応させる。同じ原画・同じ瞬間を再利用する場合は、何が新しいかと計上するかを残す。合計だけを書いて80コマと宣言せず、数えたIDを辿れるようにする。

## 一話に必要な物語の分量

一話は一つの短い予告や引きだけで終えない。主筋に、状況や目的を理解する区間、試みや応酬が深まる区間、転換と結果を受け取る区間を作る。同じ場所・同じ会話でもよく、場面転換の数を増やす必要はない。

脚本とネームで次を確かめる。

1. **入り口**：直前の結果、いまの場所と人物、その話で求めるものが追える。
2. **展開**：試み・迷い・相手の返答・発見などが次の行動を変える。要約文だけで山場へ飛ばない。
3. **山場**：読者への約束に合う対決、選択、発見、笑い、関係の転換などを十分に体験できる。
4. **結果と反応**：起きたことを人物が受け止め、知識・状況・感情・関係の何かが変わる。重要な会話は主張だけで切らず、応答と受け取った反応まで見せる。
5. **その話の満足と次への接続**：今回読んだ成果や余韻があり、次の問いが今話の結果から生まれる。決着をすべて次話へ送り、引きだけを一話の満足へ置き換えない。

例えば「依頼を聞く → 承諾 → 勝利 → 報酬」だけで急いで終わる話なら、事情への問いと応酬、準備や迷い、最初の試みと相手の応答、判断の変更、山場、結果の受け止め、次の選択のうち欠けたものを補う。新しい敵や設定を無理に追加するのではなく、既にある出来事を人物が体験する量を増やす。

場面ごとのコマ数、山場の数、会話の文字数は固定しない。「場面」は場所・時間・進める目的などが変わるまとまり、「カット」はその中で見る対象や距離を選ぶ単位として区別する。場面の数だけで長さを合格にしない。

前の五つの判定も、実際に読むコマ・声などのID範囲へ対応させる。脚本の要約に「山場と反応がある」と書いただけで、ネームの実物を確認済みにしない。

## ネーム提示前の不足判定

通常話で有効コマ80未満、または本編40画面相当未満なら、**分量の見直し対象**にする。自動的に完成扱いせず、圧縮された会話、理解に必要な動作、人物の反応、山場から結果へのつながりを探して脚本へ戻す。計測済みの自然な読了時間が8分未満なら、その所見も不足判断へ使う。人数や読む速さなどの条件を残し、速読や見慣れた作者の再読一回だけを全読者の時間として断定しない。

ネームを提示する前に、次の三つを別々に判定する。数字を満たしていても、後二つが不足なら要修正。

- **量**：通常話の目安と比べて十分か。目標値と実際の値を取り違えていないか。
- **物語**：前節の因果・応酬・山場・結果・満足が実物で読めるか。
- **水増し**：意味のない空白、同じ状態の反復、説明の言い直し、再分割だけで長くしていないか。

不足を大きな画像の拡大、余白の追加、文字の巨大化、同じ原画の反復だけで直さない。意図した余白や連続構図は保ちながら、本編の内容を補う。一話に入る内容を小分けにして話数を稼がない。必要なら、まだ採用・公開していない短い予定回の出来事を一話へ統合し、話数と後続の因果を更新する。公開済みの番号や作品は、この判断だけで統合・変更しない。

短い特別回、ギャグ、プロローグ、一場面だけの試作は対象範囲と理由を明記する。通常の一話を制作都合だけで短い特別回へ言い換えない。ユーザーが短い対象を指定した場合と、通常話の目安未達を明示して「その分量で進める」と返答された場合だけ例外として扱い、`exception` に理由・未達の値・返答内容を残す。一般的な構成への賛成だけで、量の目安未達を採用したとは解釈しない。既に指定された別の長さは優先し、根拠なく全作品の数値を一律に変えない。

## 計画と実量を記録する

`series/bible.md` に通常話の目標を記録し、各話の `storyboard.md` に予定する分量と主筋のまとまりを残す。ネームと完成原稿の計測は、それぞれの制作資料または既存の `validation.json` に記録する。既存の台帳を再利用し、同じ実量の正本を複数作らない。

最低限残す項目は、対象範囲、目標、予定の有効コマ数、実際の有効コマ数、390/360pxの本編高と画面相当数、純余白の高さ、読了時間の計測状態、三つの判定、例外理由。純余白は文字・音・視覚演出も置かない明示的な間の合計高で、画像内の白い背景全体を空白扱いしない。構成メモやUI、表紙だけの領域、既読のあらすじ、広告、あとがきは本編の計測へ含めない。

純余白は既存の間の一覧にID・待つ理由・直前の手掛かり・次に初めて出る情報・表示高を残し、合計高÷本編高の割合も診断値として記録する。割合を全作品の固定上限にはしない。本編の内容を補わず40画面へ数値を合わせるためだけに純余白を増やした案は、水増しとして要修正にする。必要な間の追加は、何が失われるかと通読所見から判断する。

```json
{
  "episodeLength": {
    "scope": "full_episode",
    "target": {"readMinutes": [8, 12], "effectivePanels": [80, 120], "screenUnits390": [40, 70]},
    "planned": {"effectivePanels": null, "storySequences": []},
    "actual": {
      "effectivePanels": null,
      "body390": {"heightPx": null, "pureGapHeightPx": null, "screenUnits": null},
      "body360": {"heightPx": null, "pureGapHeightPx": null, "screenUnits": null},
      "reading": {"status": "unmeasured", "seconds": null, "method": null, "conditions": null}
    },
    "review": {"volume": "not_checked", "story": "not_checked", "padding": "not_checked"},
    "exception": null
  }
}
```

390pxは実際の本編高÷844、360pxは実際の本編高÷800で画面相当数を記録し、小数を保持する。同じ構成を両幅で確認するが、40〜70画面の目安は390pxを基準に比較する。DOMの実際の幅・高さ、文字サイズを確認し、画像とフォントの読み込み後に本編の境界を測る。総ページ高や重複するレビュー窓の枚数を本編高の代わりにしない。

読了時間を計測する場合は、画像とフォントを読み込んだ390×844pxの本編先頭を出して開始する。手動で自然にスクロールし、本編最後の絵・文字を読み終えた時点で止める。基準は初見での連続通読一回とし、読み込み待ち・放置・アプリ切り替え等の中断を除く。人数、初見か再読か、読む幅、中断の有無を残す。再読しかできない場合はその条件を明記し、初見の時間と混同しない。作品の量を補正するときは可能なら複数の初見所見を使うが、毎回新しい読者の手配を制作の必須条件にしない。

自然な通読を計測できた場合だけ `reading.status` を `measured` にして秒数と条件を残す。推定なら `estimated` とし、その範囲・根拠を別記する。コマ数、文字数、自動スクロールの速度から計算した時間は実測ではない。AIの応答時間や画像ツールの待ち時間も読了時間に使わない。未計測のときは量・物語・通読所見から仮判定し、ネーム提示時に時間が未計測であることを伝える。未計測だけを理由に、既に採用された構成の本作画を繰り返し承認待ちにしない。

ネームでは本文の量を見せてから返答を待ち、採用された構成を本作画へ引き継ぐ。完成時には再び実量と読む順を確認し、ネームより短くなった箇所や反応の欠落があれば補修する。今回の数値は制作資料へ残し、読者向けタイトルや紹介文へ制作基準を表示しない。
