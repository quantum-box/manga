# 一話の長さと読み応え

通常の一話は、**幅390 CSS pxで本編高34,000〜60,000 CSS px、有効80〜120コマ**を基準にする。純余白を除いた内容区間高も**24,000 CSS px以上**確保する。2026-10-08のユーザー訂正に従い、分数より再現できる寸法と数量で長さを決める。これはこの制作環境の初期運用基準で、業界共通の規格ではない。新しい話の脚本・ネームと、構成を組み直す改稿で使う。既存の公開話を、このルール追加だけで一括改稿しない。

過去の4〜6分や8〜12分という時間目標、26〜30画面、少数の表示窓などを今後の通常話の合格条件にしない。通常話の制作依頼は一話全体を対象とし、長さの記録に `scope: full_episode` を残す。未記入を一場面の試作と解釈して範囲を縮めない。

## 長さを三つに分けて定義する

| 主指標 | 定義 | 通常話の基準 |
| --- | --- | --- |
| 本編高 | 幅390 CSS pxで、本編の最初の要素の上端から最後の要素の下端までのレイアウト高。意図した間は含む | 34,000〜60,000 CSS px。34,000未満は量不足 |
| 内容区間高 | 本編高から登録した純余白区間の合計高を引いた値。絵・声・音などがある区間を残す | 24,000 CSS px以上。大きな空白だけで本編高を満たさない |
| 有効コマ数 | 絵がある独立したコマ・枠のないカットのうち、新しい動き、理解、選択、結果、感情や関係の変化を読むもの | 80〜120コマを設計の目安にする |

画面相当数は本編高÷844の参考値として残す。34,000〜60,000pxは約40.3〜71.1画面で、分数への換算には使わない。読了時間は任意の補助情報とし、時間の長短や未計測を通常話の合否条件にしない。初回の長いネームで量と実際の読み心地を確かめ、その作品に必要な量を補正する。

60,000 CSS px・120有効コマは厳密な上限ではない。超えた場合は過密・冗長性・一話の区切りを見直し、必要な結果や反応を切って機械的に分割しない。

## 寸法の測定条件をそろえる

画像とフォントを読み込み、実際の本編表示幅が390 CSS pxであることを確認してからDOMの本編範囲を測る。通常の本文は表示相当で19〜22px程度の読みやすさを保ち、長さを稼ぐためだけに文字や絵を拡大しない。本文を縮小してコマを詰める方法も採らない。390×844pxを基準の表示領域とし、360×800pxは横あふれ・文字・読順の検証用に使う。

CSS pxは画面のレイアウト寸法。原画像のピクセル数、PNG/JPEGの保存解像度、DPRやスクリーンショットの倍率は別に記録する。同じ390px表示を倍率3で書き出して1170px幅にしても、一話の分量は増えていない。生の画像高を足さず、完成した表示の高さを測る。360pxや別幅の実測を、そのまま390px基準へ比較しない。

mmとページ枚数は、印刷用の仕上がり寸法・解像度・版面が決まった場合だけ使う。通常の縦読みには390px基準の高さと有効コマ数を使い、端末の物理mmや任意に分割した画像ファイル枚数を主基準にしない。

生成画像の枚数、画像ファイルの分割数、DOM要素数は有効コマ数ではない。一枚の原画に複数の独立した出来事があればそれぞれ数えられるが、同じ静止画を切り出しただけ、同じ瞬間の寄り引きだけでは増やさない。接写が新しい手掛かりや感情を見せる場合は、その理解を絵コンテへ書いて数える。

余白の声・音は別の読書要素として残す。新しい発見や返答なら物語の進みに含めるが、絵の有効コマ数へは加算しない。一つのセリフを多数の余白へ分けたこと、同じ音の反復、待ち時間だけで分量基準を満たさない。セリフの文字数は参考値として扱い、無言のアクションや静かな回へ文字の下限を強制しない。

数えるコマは、絵コンテの既存一覧へID・場面・読者が新しく理解することの一文を対応させる。同じ原画・同じ瞬間を再利用する場合は、何が新しいかと計上するかを残す。合計だけを書いて80コマと宣言せず、数えたIDを辿れるようにする。

## 一話に必要な物語の分量

一話は一つの短い予告や引きだけで終えない。主筋に、状況や目的を理解する区間、試みや応酬が深まる区間、転換と結果を受け取る区間を作る。同じ場所・同じ会話でもよく、場面転換の数を増やす必要はない。

脚本とネームで次を確かめる。

1. **入り口**：直前の結果、いまの場所と人物、その話で求めるものが追える。
2. **展開**：試み・迷い・相手の返答・発見などが次の行動を変える。要約文だけで山場へ飛ばない。
3. **山場**：読者への約束に合う対決、選択、発見、笑い、関係の転換などを十分に体験できる。
4. **結果と反応**：起きたことを人物が受け止め、知識・状況・感情・関係の何かが変わる。重要な会話は主張だけで切らず、応答と受け取った反応まで見せる。
5. **その話の満足と次への接続**：今回読んだ成果や余韻があり、次の問いが今話の結果から生まれる。決着をすべて次話へ送り、引きだけを一話の満足へ置き換えない。

例えば「依頼を聞く → 承諾 → 勝利 → 報酬」だけで急いで終わる話なら、事情への問いと応酬、準備や迷い、最初の試みと相手の応答、判断の変更、山場、結果の受け止め、次の選択のうち欠けたものを補う。新しい敵や設定を無理に追加するのではなく、既にある出来事を人物が体験する量を増やす。

場面ごとのコマ数、山場の数、会話の文字数は固定しない。「場面」は場所・時間・進める目的などが変わるまとまり、「カット」はその中で見る対象や距離を選ぶ単位として区別する。場面の数だけで長さを合格にしない。

前の五つの判定も、実際に読むコマ・声などのID範囲へ対応させる。脚本の要約に「山場と反応がある」と書いただけで、ネームの実物を確認済みにしない。

## ネーム提示前の不足判定

通常話で**本編高34,000 CSS px未満、内容区間高24,000 CSS px未満、有効コマ80未満**のいずれかなら量不足として見直す。自動的に完成扱いせず、圧縮された会話、理解に必要な動作、人物の反応、山場から結果へのつながりを探して脚本へ戻す。読了時間を長く申告しても、この量不足は解消しない。

ネームを提示する前に、次の三つを別々に判定する。数字を満たしていても、後二つが不足なら要修正。

- **量**：通常話の目安と比べて十分か。目標値と実際の値を取り違えていないか。
- **物語**：前節の因果・応酬・山場・結果・満足が実物で読めるか。
- **水増し**：意味のない空白、同じ状態の反復、説明の言い直し、再分割だけで長くしていないか。

不足を大きな画像の拡大、余白の追加、文字の巨大化、同じ原画の反復だけで直さない。意図した余白や連続構図は保ちながら、本編の内容を補う。一話に入る内容を小分けにして話数を稼がない。必要なら、まだ採用・公開していない短い予定回の出来事を一話へ統合し、話数と後続の因果を更新する。公開済みの番号や作品は、この判断だけで統合・変更しない。

短い特別回、ギャグ、プロローグ、一場面だけの試作は対象範囲と理由を明記する。通常の一話を制作都合だけで短い特別回へ言い換えない。ユーザーが短い対象を指定した場合と、通常話の目安未達を明示して「その分量で進める」と返答された場合だけ例外として扱い、`exception` に理由・未達の値・返答内容を残す。一般的な構成への賛成だけで、量の目安未達を採用したとは解釈しない。既に指定された別の長さは優先し、根拠なく全作品の数値を一律に変えない。

## 計画と実量を記録する

`series/bible.md` に通常話の目標を記録し、各話の `storyboard.md` に予定する分量と主筋のまとまりを残す。ネームと完成原稿の計測は、それぞれの制作資料または既存の `validation.json` に記録する。既存の台帳を再利用し、同じ実量の正本を複数作らない。

最低限残す項目は、対象範囲、基準の寸法と数量、予定と実際の有効コマ数、390/360pxの本編高、純余白高、内容区間高、参考の画面相当数、三つの判定、例外理由。読了時間は必要なら別記する。純余白は文字・音・視覚演出も置かない区間の合計高で、画像内の白い背景全体を空白扱いしない。構成メモや計測UI、表紙だけの領域、既読のあらすじ、広告、あとがきは本編の計測へ含めない。

純余白は既存の間の一覧にID・待つ理由・直前の手掛かり・次に初めて出る情報・表示高を残し、合計高÷本編高の割合も診断値として記録する。未登録のCSS空白や画像内の大きな無情報の空白帯も、該当区間を登録して差し引く。横並びなどで同じ縦範囲が重なる場合は二重加算しない。割合を全作品の固定上限にはしない。本編の内容を補わず34,000pxへ数値を合わせるためだけに純余白を増やした案は、水増しとして要修正にする。必要な間の追加は、何が失われるかと通読所見から判断する。

ネーム補助ツールの「構成計測」は本編高・明示的な `pause` 高・表示カット数を自動表示する。`pause` 以外の空白は自動では差し引かず、表示カット数も有効コマ数とは別物。自動値を土台に絵コンテと照合し、純余白全体と有効コマを確認する。

```json
{
  "episodeLength": {
    "scope": "full_episode",
    "target": {"widthCssPx": 390, "bodyHeightCssPx": [34000, 60000], "minContentHeightCssPx": 24000, "effectivePanels": [80, 120]},
    "planned": {"effectivePanels": null, "storySequences": []},
    "actual": {
      "effectivePanels": null,
      "body390": {"heightCssPx": null, "explicitPauseHeightCssPx": null, "pureGapHeightCssPx": null, "contentHeightCssPx": null, "screenUnits": null},
      "body360": {"heightCssPx": null, "pureGapHeightCssPx": null, "contentHeightCssPx": null, "screenUnits": null}
    },
    "review": {"volume": "not_checked", "story": "not_checked", "padding": "not_checked"},
    "exception": null
  }
}
```

390pxは実際の本編高÷844、360pxは実際の本編高÷800で参考の画面相当数を記録し、小数を保持する。同じ構成を両幅で確認するが、長さの判定には390pxでの実測値を使う。小数をUIで丸めても、合否は丸める前の値で比較する。総ページ高や重複するレビュー窓の枚数を本編高の代わりにしない。

任意で読了時間を残す場合は、読み込み後の本編先頭から最後の絵・文字を読み終えるまでの自然な手動通読を計測し、放置等の中断を除く。読む幅、初見か再読か、中断の有無を残す。計測・推定・未計測を区別し、コマ数や自動スクロールの速度、AIの応答・画像ツールの待ち時間を実測の読了時間にしない。読了時間が未計測という理由だけで本作画を止めず、寸法・数量・物語・水増しの確認を使う。

ネームでは本文の量を見せてから返答を待ち、採用された構成を本作画へ引き継ぐ。完成時には再び実量と読む順を確認し、ネームより短くなった箇所や反応の欠落があれば補修する。今回の数値は制作資料へ残し、読者向けタイトルや紹介文へ制作基準を表示しない。
